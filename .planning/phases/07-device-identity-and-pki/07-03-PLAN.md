  <behavior>
Design constants. Every later plan depends on these exactly as written.

```
IDENTITY_DIR   = Path(os.environ.get("ARLOWE_IDENTITY_DIR", "/var/lib/arlowe/identity"))
DEVICE_ID_PATH = IDENTITY_DIR / "device-id"
ENTROPY_PATH   = IDENTITY_DIR / "device-entropy"
KEY_PATH       = IDENTITY_DIR / "device.key"
CSR_PATH       = IDENTITY_DIR / "device.csr"
CERT_PATH      = IDENTITY_DIR / "device.crt"
METADATA_PATH  = IDENTITY_DIR / "identity.json"
SECRET_MODE    = 0o600
```

The env-override pattern mirrors `arlowe_config.py`'s `ARLOWE_*_PATH` constants, which is what
makes this module testable offline with fixture paths. Note the paths are read at import time, so
tests must monkeypatch the module attributes as well as the env var — copy the `_set_paths` idiom
from `test_arlowe_config.py`.

**`write_secret(path, data: bytes) -> None`**
The single writer for everything in the identity store.
- `fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_EXCL, SECRET_MODE)`, then `os.fdopen(fd,"wb")`.
- `O_EXCL` means it raises `FileExistsError` on an existing path. That is deliberate: identity
  material is written once. Callers that need replacement must remove first and say so.
- Follow up with an explicit `os.chmod(path, SECRET_MODE)`. `os.open`'s mode argument is masked by
  the process umask, so under systemd's default `UMask=0022` an `O_CREAT` with `0o600` still lands
  at `0o600` (0600 & ~0022 == 0600) but under a more permissive umask assumption this is the belt
  to the O_EXCL braces. The explicit chmod makes the mode independent of umask entirely.
- Tests must prove this under a hostile umask: `os.umask(0o000)` in the test, write, assert
  `stat.S_IMODE(path.stat().st_mode) == 0o600`.

**`read_serial() -> tuple[str, str]` returning `(source_tag, serial)`**
Try these in order and return the first that yields a non-empty value:
| order | path | source_tag |
|---|---|---|
| 1 | `/proc/device-tree/chosen/rpi-duid` | `rpi-duid` |
| 2 | `/sys/firmware/devicetree/base/serial-number` | `dt-serial` |
| 3 | `/proc/cpuinfo`, the `Serial` field | `cpuinfo` |
`rpi-duid` is preferred because it is factory-allocated rather than RNG-derived and matches the 2D
data-matrix laser-etched on the PCB, which matters for RMA and support.
Device-tree reads are NUL-terminated: strip trailing `\x00` and whitespace. Raise
`IdentitySourceUnavailable` (a module-level exception) if all three are unavailable — that is a
boundary condition on real hardware, so it validates loudly rather than defaulting.
The search roots must be overridable for tests (module-level `SERIAL_SOURCES` list of
`(source_tag, Path)` built from an `ARLOWE_SERIAL_ROOT` prefix, default `/`).

**`ensure_entropy() -> bytes`**
- If `ENTROPY_PATH` exists, read and return its 32 bytes.
- Otherwise generate `os.urandom(32)` exactly once and `write_secret` it.
- This is per-device entropy. It is NOT a TPM and NOT hardware-backed. Its purposes are:
  (a) closing the documented Pi-4-era duplicate-serial hole, (b) guaranteeing two units with the
  same serial cannot collide, (c) making the ID non-guessable from the serial alone so it is not an
  enumeration vector. Put that reasoning in the docstring — it is the non-obvious WHY.

**`derive_device_id(source_tag, serial, entropy) -> str`**
`sha256(f"{source_tag}:{serial}:{entropy.hex()}".encode()).hexdigest()[:32]` — a 32-hex-char opaque
token. Pure function, no I/O, trivially testable with known vectors.

**`ensure_device_id() -> str`**
Idempotent and stable. If `DEVICE_ID_PATH` exists, read and return it — **never re-derive**. Else
read the serial, ensure entropy, derive, `write_secret`, and also write `METADATA_PATH` (JSON, via
`write_secret`) recording `{"device_id", "serial_source", "derivation_version": 1,
"derived_at": <ISO-8601 UTC>}`. Do NOT record the raw serial in metadata — the device-id is the
opaque token by design.
Both the entropy file and the ID live on `/var/lib/arlowe`, which is a dedicated ext4 partition
(p4, owner_state) shared across A/B slots. So the ID survives a slot flip and an app OTA, and is
destroyed by factory reset (PAIR-07). That lifecycle is correct — document it.

**`resolve_hostname(template: str, device_id: str) -> str`**
`config.device.hostname` defaults to the template literal `arlowe-${device_serial}`. This function
substitutes it.

**The substitution value is `"d" + device_id[:12]`, not the raw ID.** This is not cosmetic.
`scripts/sanitize/check.sh` runs `rg -iFnH` against `scripts/sanitize/banlist.txt`, which contains
the literal `arlowe-1`. `-F` is fixed-string with no word boundaries and `-i` is case-insensitive,
so a hostname like `arlowe-1a2b3c4d` **contains** `arlowe-1` and trips the gate. Worse,
`--scan-dir` mode — the mode `scripts/build-image.sh` uses over the mounted slot-A rootfs — ignores
`.sanitize-allowlist` entirely, so there is no escape valve. The constant `d` prefix guarantees the
character immediately after `arlowe-` is a letter, and hex digits cannot spell any other banlist
entry. Result: `arlowe-d1a2b3c4d5e6`. Put the banlist reasoning in the docstring; a future
developer who "simplifies" this back to the raw ID must be told why not.

Raise `ValueError` if the template contains no `${device_serial}` placeholder.

**RED**: write `runtime/lib/tests/test_arlowe_identity.py` first and confirm it fails.
Required cases:
- `read_serial` picks `rpi-duid` when all three fixture sources exist; falls back to `dt-serial`
  when rpi-duid is absent; falls back to `cpuinfo` when both are absent; raises
  `IdentitySourceUnavailable` when none exist.
- Device-tree NUL termination is stripped (`b"ABC123\x00"` -> `"ABC123"`).
- `derive_device_id` is deterministic for fixed inputs and is 32 lowercase hex chars.
- Two different entropy values with the SAME serial produce different IDs (the collision-hole test).
- Two different source_tags with the same serial+entropy produce different IDs.
- `ensure_entropy` generates once: call twice, assert identical bytes and that the file mtime /
  content did not change.
- `ensure_device_id` is idempotent: call twice, assert identical; then corrupt the entropy file and
  call again, asserting the ID is still the persisted one (proving it never re-derives).
- Modes: with `os.umask(0o000)` set, `device-id`, `device-entropy` and `identity.json` are all
  exactly `0o600`.
- `write_secret` raises `FileExistsError` on an existing path.
- `resolve_hostname` substitutes correctly and raises `ValueError` on a template with no placeholder.
- **Banlist property test**: generate 5000 device-ids from random 32-byte entropy, resolve each
  hostname, and assert for every banned literal in `scripts/sanitize/banlist.txt` that
  `literal.lower() not in hostname.lower()`. Read the banlist from the repo — do not hard-code the
  entries, so the test tracks the real gate.
