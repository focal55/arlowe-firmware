<task type="auto">
  <name>Task 1: Add a python-test job to CI</name>
  <files>.github/workflows/ci.yml, runtime/lib/requirements-dev.txt</files>
  <action>
Create `runtime/lib/requirements-dev.txt`:

```
# Test toolchain for runtime/lib. Not installed in the firmware image.
pytest==8.3.4
```

Add a `python-test` job to `.github/workflows/ci.yml`. It must NOT be gated on the `detect` job's
`has_node` output — that gate is why nothing currently runs. The job:

```yaml
  python-test:
    name: Python tests (runtime/lib)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - name: Install deps
        run: |
          python -m pip install --upgrade pip
          pip install -r runtime/lib/requirements.txt -r runtime/lib/requirements-dev.txt
      - name: Run tests
        env:
          ARLOWE_SCHEMA_PATH: config/schema.yml
          ARLOWE_DEFAULTS_PATH: config/defaults.yml
          ARLOWE_CONFIG_PATH: /nonexistent
          PYTHONPATH: runtime/lib
        run: python -m pytest runtime/lib/tests/ -q
```

Python 3.11 matches Debian bookworm's system python3, which is what the image runs.

Do not restructure the existing Node jobs and do not add a root `package.json`. The fact that the
Node jobs are inert because no root `package.json` exists is a real repo defect, but it belongs to
the dashboard, not to Phase 7 — record it in the SUMMARY as a finding for the backlog and move on.
  </action>
  <verify>
`python3 -m pip install -r runtime/lib/requirements.txt -r runtime/lib/requirements-dev.txt` succeeds in a clean venv
`PYTHONPATH=runtime/lib ARLOWE_SCHEMA_PATH=config/schema.yml ARLOWE_DEFAULTS_PATH=config/defaults.yml ARLOWE_CONFIG_PATH=/nonexistent python3 -m pytest runtime/lib/tests/ -q` passes

Run the full suite from a fresh `git clone` of the branch into a temp directory (not the working
tree — the point is to catch state that only exists locally):

```
git clone . /tmp/arlowe-clean && cd /tmp/arlowe-clean
python3 -m venv .venv && .venv/bin/pip install -r runtime/lib/requirements.txt -r runtime/lib/requirements-dev.txt

```

Known failure class in this repo: **git does not track empty directories**, so a fixture directory
that exists only as an empty dir vanishes in a clean checkout and breaks fixture-based tests.
`runtime/lib/tests/fixtures/proc_asound/` already has at least one `.keep` for this reason; audit
every fixture subtree and add `.keep` where a directory would otherwise be empty.

Fix whatever the clean-checkout run surfaces. If a test fails for a reason unrelated to checkout
hygiene (e.g. it depends on a developer's ALSA state), make it skip explicitly with a reason rather
than deleting it — a silently deleted test is worse than a visibly skipped one.
  </action>


**Image surface** — add to `pi-gen/stage-arlowe/00-packages/00-packages-nr`, in a new commented
section (the file's existing style groups packages by purpose with a WHY comment):

```
# Phase 7 device identity / PKI (ADR-0007). The identity CLI runs under system
# python3 — /opt/arlowe/venvs is not populated by the image build — so these must
# come from apt, not pip. python3-cryptography provides P-256 keygen + CSR building;
# python3-requests provides the mutual-TLS call to the IoT credentials provider.
python3-cryptography
python3-requests
```

This file must stay inside the `00-packages/` sub-stage directory. pi-gen's `run_stage()` iterates
only directories under the stage root and reads `NN-packages-nr` from within each one; a copy at the
stage root is silently ignored (that was F7 #18, and every image built before the fix was missing
its declared package set). The existing post-pi-gen guard in `scripts/build-image.sh` parses this
list and asserts each package is `install ok installed` in the rootfs, so a correct edit here is
self-verifying at the next image build.
