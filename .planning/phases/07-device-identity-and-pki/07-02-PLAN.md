**(b) The `python-test` job.** It must NOT be gated on the `detect` job's `has_node` output — that
gate is why nothing currently runs.

```yaml
  python-test:
    name: Python tests (runtime/lib)
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - name: Install deps
        run: |
          python -m pip install --upgrade pip
          pip install -r runtime/lib/requirements.txt -r runtime/lib/requirements-dev.txt
      - name: Run tests
        env:
          ARLOWE_SCHEMA_PATH: config/schema.yml
          ARLOWE_DEFAULTS_PATH: config/defaults.yml
          ARLOWE_CONFIG_PATH: /nonexistent
          PYTHONPATH: runtime/lib
```

Python 3.11 matches Debian bookworm's system python3, which is what the image runs.

**(c) The `python-floor-bookworm` job — durable enforcement of the API floor.**
`runtime/lib/requirements.txt` pins `cryptography==43.0.3` for CI, but the image runs system
python3 against bookworm's **38.0.4** with no venv. Without this job, that constraint is a one-shot
command on a developer laptop, and the first 42+-only API call (`x509.verification`,
`not_valid_after_utc`) ships green and breaks on the device. Run the suite against the real image
surface — apt packages in a bookworm container, no pip resolution to approximate it:

```yaml
  python-floor-bookworm:
    name: Python tests (Debian bookworm API floor)
    runs-on: ubuntu-latest
    container: debian:bookworm
    steps:
      - uses: actions/checkout@v4
      - name: Install image-equivalent system packages
        run: |
          apt-get update
          apt-get install -y --no-install-recommends \
            python3 python3-cryptography python3-requests \
            python3-yaml python3-jsonschema python3-pytest
          python3 -c "import cryptography; print(cryptography.__version__)"
      - name: Run tests
        env:
          ARLOWE_SCHEMA_PATH: config/schema.yml
          ARLOWE_DEFAULTS_PATH: config/defaults.yml
          ARLOWE_CONFIG_PATH: /nonexistent
          PYTHONPATH: runtime/lib
        run: python3 -m pytest runtime/lib/tests/ -q
```

The package list must stay a superset of
`pi-gen/stage-arlowe/00-packages/00-packages-nr`'s Python entries (task 3 adds two). Add a comment
in the workflow saying so, and naming this job as the authority plan 07-06's floor claim rests on.
If this job surfaces a genuine bookworm incompatibility in **existing** `arlowe_config` code rather
than in Phase 7 code, that is a real finding: record it in the SUMMARY and fix it here, because it
means the image has been running code CI never exercised.

Two things this must NOT be resolved by:
- **Not by keeping `lint` gated off behind a false `has_node`.** `detect` emits exactly ONE
  `has_node` output consumed by all four jobs (`ci.yml:18`, and
  `if: needs.detect.outputs.has_node == 'true'` at lines 33, 50, 67, 84). There is no way to make it

and in the SUMMARY, and leave them for a dedicated dashboard plan.

recorded on #120) — but check first whether it went red only because `lint` did.

every fixture subtree and add `.keep` where a directory would otherwise be empty.
