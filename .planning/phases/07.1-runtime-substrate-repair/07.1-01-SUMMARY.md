**Excluded, with reason.** `Flask` is pinned in `runtime/face/requirements.txt` but
`face_service.py` uses stdlib `http.server` — not reachable from any unit, so it is not
installed on the device. `urllib3`/`certifi`/`idna`/`charset-normalizer` are reachable but
arrive as apt `python3-requests` dependencies.

**The two entries no grep would find.** `scipy` has no direct importer anywhere in
`runtime/` — it is a hard dependency of noisereduce and openwakeword. `sklearn` and
`joblib` have no `import` line at all: the wake-word verifier pickle is a scikit-learn
estimator, and unpickling imports sklearn *from inside `pickle.load`*. Absent them the
unit dies with a `ModuleNotFoundError` raised from a pickle frame, not from an import
statement. These are exactly the hops the F7 #18 defect class is made of.

## The Node decision, and what 07.1-03 / 07.1-04 must honor

`units/arlowe-dashboard.service:18` runs `/usr/bin/node`; bookworm's candidate is 18.20.4;
`next@16.1.6` declares `engines.node >= 20.9.0`. The unit could never have reached `active`
even once 07.1-04 produces `server.js`.

The old comment at `00-packages-nr:33` was false twice over — `runtime/dashboard/package.json`
has **no `engines` field at all** (verified: it goes `name/version/private/scripts/dependencies`),
and the binding floor comes from `next`'s own metadata.

**Decided: apt `nodejs` and `npm` are DROPPED.** Leaving 18.20.4 at `/usr/bin/node` while the
unit points elsewhere is a trap the SC1 path gate passes by construction. `npm` was unused
regardless — the dashboard is pnpm.

**The path the dashboard unit must name:** `/opt/arlowe/node/bin/node`, from
`third_party/node/manifest.yml`'s `node_bin`. The manifest also declares `install_to`
(`/opt/arlowe/node`), `tarball_root` (for `--strip-components=1`) and `version_floor`
(`20.9.0`). Plan 07.1-04 applies the `ExecStart`; plan 07.1-03's floor gate asserts the version.

**Node 24, not Node 20 — the plan's recommendation overturned.** Node 20 "Iron" reached EOL
on **2026-04-30**, four months before this ran. Shipping it would bake an unpatched runtime
into v1 for the product's life. Node 24 "Krypton" is Active LTS (end 2028-04-30) and clears
the same floor. Schedule read from `nodejs/Release/schedule.json`.

## Deviations from plan

### [Rule 1 — Bug] `--no-deps` is not a valid requirements-file directive

**Found during:** Task 2. The plan said to "comment the `--no-deps` choice in `voice.txt`",
implying a single file installable by its own verify command
(`pip install -r voice.txt -c constraints.txt`). Measured:

```
$ cat r.txt
--no-deps
noisereduce==3.0.3
$ pip install -r r.txt
ERROR: Invalid requirement: --no-deps
pip: error: no such option: --no-deps
```

`--no-deps` is a command-line flag applying to the whole invocation. Had I written the file
as the plan described, the build would have pulled the 74 MB matplotlib chain anyway and the
comment would have been decorative.

**Fix:** split the voice venv into `voice.txt` (resolver on) and `voice-nodeps.txt`
(installed `--no-deps`). **Contract for 07.1-04:** `build-venvs.sh` must run both, in order.
Running only the first yields a venv where `import noisereduce` fails. Documented in both
file headers and ADR-0008. Commit `33e9ced`.

### [Rule 1 — Bug] `huggingface_hub` / `tokenizers` cannot be shared constraints

**Found during:** Task 2. The plan named both as `constraints.txt` entries. Measured, the two
venvs cannot agree: `transformers<5` caps `huggingface_hub` below 1.0 (resolves 0.36.2) while
`faster-whisper` wants 1.x (resolves 1.31.0); `tokenizers` follows at 0.22.2 vs 0.23.2.
Constraining either would make one unit uninstallable.

**Fix:** pinned per-venv in `llm.txt` and `stt.txt`, with a block in `constraints.txt`
explaining the exclusion so it is not "fixed" later. Commit `33e9ced`.

### [Repo contradicts plan] `fonts-dejavu-core` omitted

**Found during:** Task 1. The plan listed it for the recovery renderer. The repo says
otherwise: `runtime/recovery/arlowe-recovery.sh:96` imports `ImageFont` but **never calls it**,
and the `anchor="mm"` its `draw.text` calls pass was measured working with Pillow 9.4.0's
built-in bitmap font:

```
--- default-font anchor test (reproduces arlowe-recovery.sh:102) ---
anchor OK with default font
--- is any TTF present without fonts-dejavu-core? ---
(end ttf search)
--- fonts-dejavu-core installed size ---
2960 KiB
```

2.9 MB of unreferenced data. Omitted, with the measurement recorded in the file's comment and
in ADR-0008. **Follow-up (cosmetic, not a defect):** the built-in font is fixed at ~11px, so
recovery text is small on the 240x280 display. Fixing that means editing `arlowe-recovery.sh`
to load a TrueType face — and *that* change is what would justify the font package.

### [Rule 2 — Missing critical] Node 20 is end-of-life

**Found during:** Task 3. The plan and the manifest shape both said "Node 20 LTS". Node 20
"Iron" ended 2026-04-30 — shipping it means a consumer device with a permanently unpatched
JS runtime. Moved to Node 24 Krypton (Active LTS, end 2028-04-30), which satisfies the same
`>= 20.9.0` floor. Evidence table in ADR-0008. Commit `e474060`.

### [Rule 2 — Missing critical] The Node tarball was not gitignored

**Found during:** Task 3. `third_party/node/INSTALL.md` instructs builders to place the
tarball at `third_party/node/<filename>`, and `git check-ignore` confirmed no rule covered
it — a ~30 MB binary one `git add` away from the history, in a repo whose existing convention
(`third_party/axcl/*.deb`) is explicitly "NEVER commit". Added
`third_party/node/*.tar.{xz,gz}` to `.gitignore`. Commit `e474060`.

## Concerns for later plans

1. **Slot sizing.** The three venvs add ~552 MB per slot, ~1.1 GB across A and B. ADR-0004's
   "model-free slot footprint ≈ 2–3 GB", on which its **"16 GB is VIABLE"** conclusion rests,
   was estimated when `/opt/arlowe/venvs` was empty. Plan 06-04's measure-then-set should
   re-measure before partition numbers are fixed, and the 16 GB claim re-checked rather than
   assumed to survive. Flagged in ADR-0008's Consequences.
2. **`RPi.GPIO` cannot be import-tested off-hardware** (see above). 07.1-05 must special-case it.
3. **`verify-third-party.sh` now has four near-identical hardcoded manifest blocks.** The gate
   has no generic iteration — lines 19–22 name each manifest by hand. The duplication is now
   worth a cleanup, but rewriting the build's hash gate is not substrate repair; recorded here
   rather than done.
4. **Node security updates are a manual bump.** A vendored tarball gets no `apt upgrade`.
   `third_party/node/INSTALL.md` documents the five fields that move together; this should
   become a recurring maintenance item, not a surprise.
5. **No `files/` staging mechanism was added to `00-run.sh`.** Only `third_party/node` went
   into the staging loop. Getting `venv-requirements/` into the chroot remains plan 07.1-04
   Task 1's to resolve, as the plan reserved — I did not pre-empt it, so 04 will not find a
   half-built second mechanism.
