  <files>runtime/voice/wake_gate.py</files>
  <action>
Create `runtime/voice/wake_gate.py`. It must import nothing outside the standard library —
`os`, `pickle`, `pathlib`, `typing` only. No numpy, no sklearn, no openwakeword. That constraint is
what makes it testable in the cheap `python-test` CI job instead of requiring the full voice venv.

Constants, taken from the README's documented contract and the current code:
  GENERIC_BASE_THRESHOLD = 0.7    # no verifier: the base model is the only gate
  VERIFIED_BASE_THRESHOLD = 0.20  # verifier present: base is a cheap pre-filter (current BASE_THRESHOLD)
  VERIFIER_THRESHOLD = 0.30       # current VERIFIER_THRESHOLD

API:

  def load_verifier(path) -> object | None
      Returns None if `path` does not exist. Otherwise unpickles and returns the classifier.
      A corrupt or unreadable pickle must ALSO return None with a message on stderr rather than
      raising — a device that cannot read its own personalization file should degrade to the
      generic model, not refuse to boot. Catch `Exception`, not bare `except:`.

  class WakeGate:
      def __init__(self, verifier_path, ...)
      @property personalized -> bool          # verifier is not None
      @property base_threshold -> float       # VERIFIED_BASE_THRESHOLD if personalized else GENERIC_BASE_THRESHOLD
      def evaluate(self, base_score, features_fn) -> tuple[bool, float | None]
          features_fn is a zero-arg callable returning the flattened feature vector. It is called
          ONLY when personalized and only after base_score clears base_threshold — do not pay for
          feature extraction on a generic device.
          Returns (accepted, verifier_score). verifier_score is None when not personalized.

Docstring the module with the two operating modes and the fact that generic mode is the shipped v1
configuration (personalization is WAKE-03/WAKE-04, post-v1).
  </action>
