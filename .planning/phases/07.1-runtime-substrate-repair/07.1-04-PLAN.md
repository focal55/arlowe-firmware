dashboard's `server.js`.

the Node runtime decided in ADR-0008.

  <action>
Write `pi-gen/stage-arlowe/01-runtime/files/build-venvs.sh`, run inside the chroot as root. For each
of `voice`, `llm`, `stt`:

  python3 -m venv --system-site-packages /opt/arlowe/venvs/<name>
  /opt/arlowe/venvs/<name>/bin/pip install --no-cache-dir \
      -r <staged>/venv-requirements/<name>.txt -c <staged>/venv-requirements/constraints.txt

`--system-site-packages` is the decision recorded in ADR-0008: it lets the venvs see the apt-supplied
compiled packages (numpy, Pillow, scipy, sklearn, joblib, PyAudio) instead of building them, which
is what makes the build work identically on the native-arm64 CI runner (`ubuntu-24.04-arm`) and on
arlowe-1. Do not change this without amending the ADR.

Then set ownership and permissions consistent with the rest of `/opt/arlowe`: root-owned, readable
and traversable by the `arlowe` group (`install-arlowe-fs.sh` uses `root:arlowe 0755` throughout).
The units run as `User=arlowe` under `ProtectSystem=strict`, so the interpreters must be executable
by that user and nothing under `/opt/arlowe/venvs` may need to be writable at runtime.

After install, assert in-script — do not defer this to the outer gate:
  - `/opt/arlowe/venvs/<name>/bin/python` exists and is executable
  - `pip check` reports no broken dependencies in each venv
  - `pip freeze --local` output is written to `/opt/arlowe/venvs/<name>/FROZEN.txt` and echoed to the
    build log. That file is the on-device record of what was installed; a support engineer reading a
    failed device should not have to guess.
Exit non-zero on any failure.

WIRING. Read `00-run-chroot.sh` before editing. Its step order matters and has a documented defect
history: CLI symlinks used to run before their targets existed, which made F7 #21 invisible until
hardware. Insert the call where inputs exist:
  - AFTER the `rsync -a --chown=root:arlowe "${REPO_ROOT}/runtime/" /opt/arlowe/runtime/` at ~line 95
    (build-venvs does not need it, but the dashboard build in Task 2 does, and keeping both new steps
    together keeps the order legible)
  - AFTER `step 6: install-arlowe-cli.sh` (~line 110)
  - BEFORE the reproducibility-cleanup block at the end, which does `rm -rf /root/arlowe-build`,
    `apt-get clean`, `rm -rf /var/lib/apt/lists/*` and a `__pycache__` purge. Running after any of
    those breaks the build: the requirement files live under the staged tree.
Renumber the step comments. The existing "step 7: extract-axcl-udev-from-deb.sh" comment must move to
whatever number it now occupies, and the header block at lines 9-16 must be updated to match. The
brief for this phase asks for this explicitly.

Note in a comment that the cleanup block's `find /opt/arlowe -name "__pycache__" -exec rm -rf` will
strip the venvs' bytecode caches. That is intended (determinism) and costs only first-start latency;
say so, so a later reader does not "fix" it.

The requirement files must reach the chroot. They live under
`pi-gen/stage-arlowe/01-runtime/files/`, which is NOT the staged repo tree — check how
`03-firstboot/00-run-chroot.sh` gets at `03-firstboot/files/` and follow the same mechanism. If
pi-gen does not expose the sub-stage `files/` dir inside the chroot, have the host-side
`00-run.sh` copy them into `/root/arlowe-build/` alongside the repo, and say which mechanism you
used in the SUMMARY.

Finally, correct `scripts/provision/install-arlowe-fs.sh:51`. It currently says Phase 6 populates the
venvs. Replace with a comment stating that `/opt/arlowe/venvs` is created empty here and populated by
`pi-gen/stage-arlowe/01-runtime/files/build-venvs.sh` from the pinned requirement files, naming the
path. A stale deferral comment is how this gap survived two phases.
  </action>
  <verify>

Python is irrelevant here:

  docker run --rm --platform linux/arm64 -v "$PWD:/repo" debian:bookworm bash -c '
    set -e
    apt-get update -qq >/dev/null
    mapfile -t P < <(sed "s/#.*//" /repo/pi-gen/stage-arlowe/00-packages/00-packages-nr | tr -s "[:space:]" "\n" | grep -v "^$")
    apt-get install -y -qq --no-install-recommends "${P[@]}" >/dev/null
    groupadd --system arlowe && useradd --system -g arlowe -d /var/lib/arlowe -s /usr/sbin/nologin arlowe
    mkdir -p /opt/arlowe/venvs /root/arlowe-build
    cp -r /repo/pi-gen/stage-arlowe/01-runtime/files /root/arlowe-build/
    bash /repo/pi-gen/stage-arlowe/01-runtime/files/build-venvs.sh
    for v in voice llm stt; do
      test -x /opt/arlowe/venvs/$v/bin/python || { echo "MISSING $v"; exit 1; }
      echo "--- $v ---"; /opt/arlowe/venvs/$v/bin/pip check; head -5 /opt/arlowe/venvs/$v/FROZEN.txt
    done
    echo VENVS_OK
    du -sh /opt/arlowe/venvs'
