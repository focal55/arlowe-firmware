# Phase 07.1 Plan 02: Wake gate for the factory state Summary

**`arlowe-voice` no longer crash-loops on a device that has never been personalized: the unguarded `pickle.load` is replaced by a stdlib-only `WakeGate` that runs the base model alone at threshold 0.7 when no verifier exists, and the wake-word README now describes the code that actually ships.**

## Accomplishments

- **SC5 closed at the code level.** `runtime/voice/voice_client.py` opened `/var/lib/arlowe/wake-word/verifier.pkl` with no existence check. That file is absent on every factory device, so the unit raised `FileNotFoundError`, `Restart=on-failure` fired, and `arlowe-voice` looped forever without ever reaching its listening loop. There is now no code path in `runtime/voice/` that opens the verifier without checking first.
- **One definition of each threshold.** `BASE_THRESHOLD` and `VERIFIER_THRESHOLD` were deleted from `voice_client.py`. Both numbers, plus `GENERIC_BASE_THRESHOLD`, now live only in `wake_gate.py`. The README/code drift this plan fixes was caused by two copies of the same number.
- **Corrupt verifiers degrade rather than raise.** A truncated or unreadable `.pkl` is treated exactly like an absent one, with a stderr line explaining the fallback.
- **Doc reconciled with a visible correction.** The README's "Generic-model swap path" section documented an `if not VERIFIER_MODEL.exists()` branch and asserted a prior plan had wired it. No such branch existed. Replaced with the implemented behaviour plus a dated correction note.

## Decisions Made

1. **`runtime/voice/tests/` has no `__init__.py`.** `runtime/lib/tests/` has one, so this breaks convention. Reason: with `__init__.py`, pytest's rootdir-prepend import mode names the module `tests.test_wake_gate` and inserts `runtime/voice` on `sys.path`. `runtime/lib/tests` already claims the top-level package name `tests`. If 07.1-05 ever collects both suites in one pytest invocation, two different directories would resolve to the same `tests` package. Without `__init__.py`, the module is imported as bare `test_wake_gate` and the collision cannot occur. 07.1-05 must not "fix" this by adding the file.
2. **Absent and corrupt verifiers collapse into one case.** `load_verifier` catches `Exception` (not bare `except:`) and returns `None` with a stderr line. The alternative - surfacing corruption as an error - reintroduces the exact crash-loop this plan removes, just with a rarer trigger.
3. **`WakeGate` accepts an injected verifier.** `WakeGate(path, verifier=obj)` skips disk entirely; `verifier=None` forces generic mode. Distinguished from "not supplied" by a module-level sentinel. Lets 07.1-05 and future callers exercise `evaluate` without pickling.
4. **The diagnostic scripts were left alone.** `quick_test.py` (base 0.7 / verifier 0.5) and `test_verifier.py` (base 0.3 / verifier 0.6) carry their own hardcoded numbers. They are bench tools that are meant to be tuned away from the shipping policy, and they are outside this plan's `files_modified`. The README now states explicitly that their thresholds are not the device's behaviour. **Follow-up candidate, not a blocker.**
5. **The `'jarvis'` base-model hardcode at `voice_client.py:344` was not touched.** It belongs to Phase 8.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `WAKE DETECTED` banner would raise `TypeError` in generic mode**

- **Found during:** Task 2 (wiring voice_client to the gate)
- **Issue:** After the accept branch, the pre-existing lines formatted the verifier score directly: `print(f"WAKE DETECTED (v:{verifier_score:.2f})")` and the matching `log_voice(...)`. In generic mode `verifier_score` is `None`, and `format(None, '.2f')` raises `TypeError`. The plan's Task 2 instructions covered the *near-miss debug* line but not these two. Left unfixed, a factory device would have started successfully - the plan's stated goal - and then crashed on its first real wake word, which is arguably a worse failure than the crash-loop because it only reproduces with a human in front of the device.
- **Fix:** Compute a `score_label` before the banner: `v:{verifier_score:.2f}` when personalized, `base:{base_score:.2f}` when generic. Both log lines use it.
- **Files modified:** `runtime/voice/voice_client.py`
- **Verification:** `py_compile` in the bookworm container; the `None` path is exercised at the policy level by `test_generic_above_threshold_accepts`, which asserts `evaluate` returns `(True, None)`.
- **Committed in:** `38d316b` (part of the Task 2 commit)

**2. [Rule 2 - Missing Critical] README named an environment variable the orchestrator does not read**

- **Found during:** Task 3 (README reconciliation)
- **Issue:** The stale section's code snippet showed `voice_client.py` reading `ARLOWE_WAKE_WORD_VERIFIER`. It reads `ARLOWE_VERIFIER_MODEL`. The "Env knobs" table listed only the former. This is not hypothetical: `docs/operations/phase-1-smoke-test.md:13` records this exact mix-up causing a `FileNotFoundError` during the Phase 1 smoke test because the unit set the variable nobody reads. Rewriting the section while leaving the wrong variable name in the table would have re-armed the same trap.
- **Fix:** Env-knobs table now lists both variables and states which consumer honours each. The "State on disk" paragraph and the correction note both call out the split.
- **Files modified:** `runtime/wake-word/README.md`
- **Verification:** `grep -rn "ARLOWE_VERIFIER_MODEL"` confirms `voice_client.py:45` and `units/arlowe-voice.service:17` agree with what the README now says.
- **Committed in:** `8fb99d3` (part of the Task 3 commit)
