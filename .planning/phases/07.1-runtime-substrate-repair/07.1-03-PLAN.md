<objective>
Build the durable deliverable of this phase: a build-time gate that parses every shipping unit's
`ExecStart=` / `ExecStartPre=` family and fails the build when the named interpreter or script is
absent from the built rootfs.

Purpose: the empty venvs, the missing `server.js`, and the undeclared Pillow import are three
instances of one class — an artifact a unit depends on that nothing in the build produces, invisible
until a device boots. `scripts/build-image.sh:141-167` already has the right shape for this in its
declared-packages guard, and that guard's own comment names its limit: it checks that *declared*
packages landed, so it can never see a thing that was never declared. This gate inverts that. Its
expectations are derived from the units themselves, so it covers things nobody remembered to declare.
Then close the hole the path gate leaves open. A path check cannot tell a Node 20 from a Node 18, and
`00-packages-nr:34` installs bookworm's 18.20.4 at `/usr/bin/node` — which is precisely the path
`units/arlowe-dashboard.service:18` names today. Existence-only, that unit PASSES and the dashboard
still never starts. So this plan ships a second assertion beside the first: the interpreter a unit
names must report a version at or above a declared floor.
Output: two reusable shell assertions, a self-test whose negative cases reproduce today's broken image
and the Node-18 trap, the wiring into the build, and the CI job that keeps watching the self-test.

SIZE, decided at plan time so nobody discovers it at push time: this plan is deliberately NOT split.
Its only obvious seam would put two wave-1 plans concurrently writing
`scripts/lib/verify-unit-execstart.sh`, which is the worktree-collision class this project has already
been bitten by. Two functions, a shared systemd parser, a twelve-case fixture suite and the CI wiring
will land at or through 600 net lines. Expect to exceed the 400-line warning and probably the 600-line
cap, and apply the `size:phase-branch` label on the PR — `pr-checks.yml` documents that label as a
deliberate human act that re-triggers the check and leaves a record. Do not split the file to get
under the number.
</objective>

  <name>Task 1: Write the gate</name>
  <files>scripts/lib/verify-unit-execstart.sh</files>
  <action>
Create `scripts/lib/verify-unit-execstart.sh` exposing `verify_unit_execstart <rootfs-prefix>`,
following the file shape of `scripts/lib/identity-store-check.sh` (sourceable library, one exported
function, testable against a fixture tree, no dependence on being run from the repo root).

DERIVATION, not enumeration. The unit set comes from globbing
`"<rootfs>/etc/systemd/system/"*.service`. Do not read `units/*.service` from the repo: the rootfs
also carries `arlowe-firstboot.service`, which `pi-gen/stage-arlowe/03-firstboot/00-run-chroot.sh`
writes directly and which never passes through `units/`, and the slot-B rootfs carries
`arlowe-recovery.service`. A repo-side list would miss both. Fail loudly if the glob matches zero
units — an empty unit set silently passing is the same defect class this gate exists to close.

For each unit, extract every `ExecStart=`, `ExecStartPre=`, `ExecStartPost=`, `ExecStop=`,
`ExecStopPost=`, `ExecReload=` assignment. Handle:

  - systemd line continuations (`\` at end of line) — join before parsing.
  - The special prefix characters systemd allows before the path: `@ - : + ! |`. Strip them, but
    remember whether `-` was present.
  - An EMPTY assignment (`ExecStart=`) is systemd's reset syntax; skip it.

For each resolved command line:

  (a) EXECUTABLE — the first whitespace-separated token after prefix stripping. systemd requires it
      to be absolute. Assert `<rootfs><token>` exists and is executable, resolving symlinks WITHIN
      the rootfs (a symlink whose target is absolute must be re-rooted at `<rootfs>` before the
      existence test — `/usr/local/sbin/arlowe-ab -> /opt/arlowe/runtime/cli/ab` is exactly the
      F7 #21 dangling-symlink shape and the gate must catch it). A dangling symlink is a FAILURE.

  (b) SCRIPT ARGUMENTS — any subsequent token that begins with `/` and either ends in
      `.py` / `.js` / `.sh` or lies under `/opt/arlowe/`. Assert it exists in the rootfs. This is
      what catches `ExecStart=/usr/bin/node /opt/arlowe/runtime/dashboard/server.js` and
      `ExecStart=/opt/arlowe/venvs/stt/bin/python /opt/arlowe/runtime/stt/stt_server.py`.
      Existence only, not the execute bit — an interpreter argument need not be executable.

  (c) UNRESOLVABLE — a token containing `$` (env interpolation) or `%` (a systemd specifier) cannot
      be resolved statically. Emit an explicit `SKIP <unit>: <token> (env/specifier interpolation)`
      line and do not count it as a pass. Print the SKIP total at the end. Silent skipping is how
      gates rot.

  (d) `-`-prefixed stanzas mean systemd tolerates their failure. Report those as WARN rather than
      FAIL, but still print them. Document the choice in the file header.

State in the header what `verify_unit_execstart` deliberately does NOT cover, so the limit is on the
record: it proves a path exists and is executable, never that the binary there can run what it is
handed. Module-import resolution is plan 07.1-05's job; end-to-end runtime behaviour is SC6's.
Interpreter version is the SECOND function in this same file — cross-reference it and ADR-0008.

SECOND FUNCTION — `verify_unit_runtime_versions <rootfs-prefix>`. This is an ASSERTION, not an
instruction someone has to remember to follow. Same file, same style, same all-failures-at-once
reporting.

  - Reuse the Exec* parser from `verify_unit_execstart` (factor it into a shared internal helper;
    two copies of a systemd line parser is the drift this phase exists to eliminate). For each
    stanza take the interpreter token — the executable, after prefix stripping.

  - Look the token up against a DECLARED FLOOR TABLE, a commented table at the top of the file, each
    entry citing its authority:
        node    -> 20.9.0   (next@16.1.6 `engines.node`; ADR-0008. Bookworm's nodejs is 18.20.4.)
        python3 -> 3.11.0   (bookworm's system python3; the venv interpreters inherit it)
        python  -> 3.11.0   (same; venvs expose both names)
    Match on the resolved basename, following symlinks inside the rootfs, so the table covers
    `/usr/bin/node`, `/opt/node/bin/node` and `/opt/arlowe/venvs/*/bin/python` alike without
    enumerating paths. Adding a floor is a one-line table edit; the ADR is the place the reasoning
    lives.

  - A token whose basename is NOT in the floor table is checked against `EXPECTED_UNDECLARED`, a
    second commented table beside the floor table listing the exact `Exec*` tokens that legitimately
    have no version floor. Report each as `UNDECLARED <unit>: <path>`, and FAIL when the observed
    undeclared set is not a SUBSET of the allowlist. Naming is not gating: this is the only branch
    through `verify_unit_runtime_versions` that would otherwise be open, and an already-noisy
    already-green category is exactly the `00-packages-nr` shape that produced F7 #18 one layer up.
    A genuinely new interpreter must not be able to arrive as one more line in a passing list.

    Seed the allowlist with the six tokens the current tree actually emits — enumerated from every
    `Exec*` stanza in `units/*.service`, `pi-gen/stage-arlowe/03-firstboot/` and
    `runtime/recovery/arlowe-recovery.service`, each with a one-line reason:
        /bin/touch                                     (coreutils; firstboot ExecStartPost marker)
        /opt/arlowe/runtime/cli/arlowe-grow-models     (first-party shell/binary entry point)
        /opt/arlowe/runtime/cli/boot-check             (first-party entry point)
        /opt/arlowe/runtime/cli/identity               (first-party entry point)
        /opt/arlowe/runtime/llm/run_api.sh             (first-party shell wrapper; execs a venv python itself)
        /opt/arlowe/runtime/recovery/arlowe-recovery.sh (slot-B recovery unit; first-party shell)
    Confirm that set against the tree before writing it — if the tree disagrees, the tree is right.
    Match on the LITERAL token as written in the unit, before symlink resolution, not on the resolved
    path: bookworm is usrmerge, so `/bin/touch` resolves to `/usr/bin/touch`, and keying on the
    resolved path would make the allowlist disagree with what a reviewer reads in the unit file and
    what a diff shows.

  - PROBE by executing the binary inside the rootfs: `chroot "<rootfs>" "<abs-path>" --version`.
    `build-image.sh` runs on a native arm64 host (`ubuntu-24.04-arm` in CI, arlowe-1 locally), so this
    is a native exec, not qemu. Assert that: compare the host's `uname -m` against the rootfs's
    architecture before probing. If they do not match, or if chroot is unavailable, that is a HARD
    ERROR with its own distinct message — never a SKIP, never a PASS. The surrounding code's rule
    already says a test that cannot be performed is a hard error; this follows it.

    Name the arch-detection mechanism in the file header rather than leaving it to the reader:
    `dpkg --print-architecture --root="<rootfs>"` (or equivalently reading the rootfs's own dpkg
    data), falling back to the ELF `Machine` field of `<rootfs>/bin/bash` if dpkg data is absent.
    Map to `uname -m` explicitly (`arm64` <-> `aarch64`, `amd64` <-> `x86_64`); a string compare of
    the two vocabularies would hard-error on a correct native build.

    Word the mismatch message precisely, because binfmt makes the obvious wording wrong:
    `build-image.yml:62` installs `qemu-user-static` and `binfmt-support` even on the arm64 runner,
    so if that runner ever moves to x86 the chroot exec would SUCCEED under emulation while this
    check hard-errors. The message must read "refusing to probe a <rootfs-arch> rootfs from a
    <host-arch> host under emulation — version results would not be the device's", not anything
    implying chroot is broken.

  - COMPARE with `dpkg --compare-versions "$got" ge "$floor"` (dpkg is on the build host). Strip a
    leading `v` from Node's output. If `--version` exits non-zero or emits nothing parseable, that is
    a FAIL naming the unit and the path, not a skip.

  - PROBE OVERRIDE, for the self-test only. Honor an `ARLOWE_VERSION_PROBE` environment variable: a
    command invoked as `$ARLOWE_VERSION_PROBE <rootfs> <abs-path>` that echoes a version string.
    This is what lets the fixture test pin a fake Node 18.20.4 at an ExecStart path without shipping
    an arm64 binary in the test tree. Document in the header that it exists for the self-test and
    that `build-image.sh` must never set it — and have the function log loudly when the override is
    active, so an accidentally-exported variable cannot make a real build's gate lie.

Output format: mirror the `log`/`ok`/`fail` helper style already used in `scripts/build-image.sh`.
Collect ALL failures and print them together before returning non-zero; a gate that stops at the
first failure turns one build into five.

  - `grep -n "20.9.0" scripts/lib/verify-unit-execstart.sh` shows the declared Node floor with its ADR-0008 citation.
  </verify>
  <done>`verify_unit_execstart` parses a rootfs's own units, classifies each Exec* target as PASS/FAIL/WARN/SKIP, reports all failures at once, and returns non-zero on any FAIL. `verify_unit_runtime_versions` probes each named interpreter against a declared floor table, returns non-zero below floor, names UNDECLARED interpreters, and hard-errors rather than skipping when it cannot probe.</done>
