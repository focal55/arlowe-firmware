<objective>
Produce the dependency ledger the image build has never had: for every third-party module a unit
entry point imports, a single declared source (apt or pinned pip), plus the ADR that records why.

Purpose: `/opt/arlowe/venvs` was never populated partly because nobody ever wrote down what
should go in it. `runtime/*/requirements.txt` are dev pins captured from the founder's dev unit
(`numpy==2.3.5`, `Pillow==11.1.0`) and are NOT installable as-is against Debian bookworm's system
layer — bookworm ships numpy 1.24.2 and Pillow 9.4.0. Installing the dev pins into a venv would
shadow the apt layer that the *system-python* consumers (`arlowe-identity-init`, `boot-check`)
already depend on, producing two divergent numpy builds in one image. This plan decides the split
once, writes it down, and makes it machine-readable so plan 07.1-04 is a mechanical application.
Output: an amended apt list, three pinned venv requirement files plus a shared constraints file,
a SHA-pinned Node manifest, and ADR-0008.
</objective>
