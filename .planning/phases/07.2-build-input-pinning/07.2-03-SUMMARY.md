## What was actually proven, and how

### SOURCE_DATE_EPOCH, both branches exercised

The derivation block was extracted from `build-image.sh` by line range and run
against this repo in both states, so the evidence comes from the shipped text
rather than a paraphrase of it:

```
dirty:  SOURCE_DATE_EPOCH: 1789886669 (2026-09-20T06:44:29Z, commit 6e8ef42)
        [WARN] Worktree has uncommitted changes to tracked files.
        ARLOWE_WORKTREE_CLEAN=false
clean:  SOURCE_DATE_EPOCH: 1789886856 (2026-09-20T06:47:36Z, commit 031f2b7)
        ARLOWE_WORKTREE_CLEAN=true
both:   matches `git log -1 --format=%ct` exactly
```

`grep -n SOURCE_DATE_EPOCH scripts/build-image.sh` now returns the derivation
(76), the export (84), the log line (97) and the `sudo` variable list (228). The
last one is the one that silently does not work if omitted.

### The clamp, on the build host with GNU find/touch

Four cases, all measured:

```
CASE A  before: 4 paths newer than epoch -> clamped 4 -> after: 0
        symlink own mtime: 1700000000 (its own, not its target's)
CASE B  unset SOURCE_DATE_EPOCH            -> rc=1, names the sudo variable list
CASE C  SOURCE_DATE_EPOCH=not-a-number     -> rc=1
CASE D  missing /opt/arlowe                -> rc=1, refuses to report 0 clamped
```

Case D is the one that matters: without it, a stage that installed nothing would
print "clamped 0 paths" and pass. `git ls-files -s` records `100755` —
`run_sub_stage` guards with `[ -x ]` and skips a non-executable run script with
no log line at all.

### The recorder refuses the three inputs that would poison the baseline

15/15 on the build host and in CI. The load-bearing cases:

```
[PASS] [empty-admindir] zero resolved packages is a hard failure, not an empty baseline
[PASS] [unpinned-rootfs:empty-sources] refused (rc=1) and wrote no manifest
[PASS] [unpinned-rootfs:deb822]        refused (rc=1) and wrote no manifest
[PASS] [observed-kernel] kernel_version 9.9.9 read from the fixture's /lib/modules
[PASS] [observed-snapshot] recorder never reads the overlay declaration
```

The fixture's kernel is `9.9.9`, a version that appears in no manifest in this
repo, so a recorder reading `third_party/kernel/manifest.yml` instead of the
rootfs fails that case rather than coincidentally agreeing.

`grep -n 'overlays/pi-gen' scripts/record-build-inputs.sh` returns nothing. The
overlay path is deliberately absent from the file including its comments, so the
check is a plain grep rather than one that has to skip comments — the same
reasoning that kept the rolling mirror's hostname out of the overlay files in
07.2-01.

The host's own deb822 layout is asserted as its own case rather than swallowed:

```
$ scripts/record-build-inputs.sh --rootfs / --out /tmp/m-host
[record-build-inputs] FAIL: /etc/apt/sources.list names no snapshot.debian.org timestamp.
rc=1, no manifest written
$ stat -c "%s bytes" /etc/apt/sources.list
0 bytes
```

### The double resolve was falsified, not just asserted

Forcing `https://` in a throwaway container copy of the overlay (stock
`debian:bookworm` ships no `ca-certificates`):


The non-zero exit comes from the step-2 assertion specifically, not from an

## Deviations from plan

### 1. [Rule 3 — blocker] The apt index was deleted before the gate that reads it

**Found during:** reading `01-runtime/00-run-chroot.sh` while placing the clamp sub-stage.
**Commit:** `3f72661`

`stage-arlowe/01-runtime/00-run-chroot.sh` ran `rm -rf /var/lib/apt/lists/*`
in-chroot. That is strictly earlier than every gate in `build-image.sh`, including
07.2-01's snapshot pin observation gate, which reads exactly that directory at the
end of the build. Consequences:

- its first assertion (`SNAPSHOT_LISTS == 0` → `exit 1`) would have **aborted every
  completed build**, which is the build plan 04 owns;
- its third assertion (zero rolling-mirror list files) — identified in the 07.2-01
  SUMMARY as *the* check that catches a partially applied overlay — **could never
  fire**, because zero list files trivially contain zero off-pin list files.

Measured rather than inferred: pi-gen's `scripts/common` and `build.sh` contain no
`apt-get update`; stage-arlowe's only package list is `00-packages/00-packages-nr`
in sub-stage 00, before 01-runtime; `copy_previous` excludes only
`var/cache/apt/archives`. Nothing repopulates the directory afterwards.

The 136 MB still must not ship, so the deletion moved into `build-image.sh`
immediately after the gate and well before measurement and partitioning. The
07.2-01 comment claiming `export-image/02-set-sources` was the only deleter is
corrected — true of pi-gen, never true of stage-arlowe.

### 2. [Rule 1 — bug] CI's `**` globs matched one directory level, not all

**Found during:** running CI's own shellcheck invocation rather than `-S warning`, as the handoff directed.
**Commit:** `6e8ef42`

Actions runs the step with bash, where `globstar` is off by default, so `**`
degrades to `*`. Measured expansion of the globs added in `649bb7d`:

```
overlays/pi-gen/**/*.sh      -> 1 file  (overlays/pi-gen/stage0/prerun.sh)
pi-gen/stage-arlowe/**/*.sh  -> 5 files (all at depth 2)
```

Six shell files in those trees were never linted, **including
`overlays/pi-gen/stage0/02-firmware/00-run.sh`** — the pinned-kernel installer,
which is the file that glob was added specifically to cover. Replaced with `find`
over the two trees, which also prints the count, because a glob silently matching
less than intended is the defect being fixed and a bare invocation cannot show it.
Coverage went 6 → 13 files.

### 3. [Rule 1 — bug] A local shellcheck pass is not evidence about CI

**Found during:** the first CI run on this branch, which failed Shellcheck despite a clean local run at default severity.
**Commit:** `17740f0`

Ubuntu 24.04 installs **shellcheck 0.9.0**, which reports SC2002 at default
severity. Local **0.11.0** made that check optional and reports it nowhere. So the
handoff's warning that `-S warning` is weaker than CI has a second layer: the
toolchain *version* matters as much as the severity flag. The finding itself was
pre-existing in a 07.2-01 file and only became visible because deviation 2 made CI
actually lint it.

Suppressed rather than rewritten, matching the `SC2001` disable a few lines above:
the line is upstream pi-gen's verbatim, and `gpg --dearmor < file` would be a
behaviour-identical edit whose only effect is to make the overlay diverge from
upstream in one more place. `overlay_sha256` re-recorded as the digest coupling
requires; `upstream_sha256` untouched, because upstream did not change.
`test-pigen-overlay.sh` is 7/7 with the new digest.

Verification is now done against CI's real toolchain: shellcheck 0.9.0 in an
`ubuntu:24.04` container, running the workflow step's own text extracted from
`pr-checks.yml` by YAML parse, exits 0 over all 13 stage/overlay scripts.

### 4. Plan text corrected by measurement

Four places where the plan's `<verify>` would have measured nothing or could
never pass, each fixed in code rather than by loosening the check:

| Plan said | Measured | Fix |
|---|---|---|
| assert a `*_Packages` list file exists | bookworm's apt stores `*_Packages.lz4`; the pattern matches **zero** files on a healthy run — it could never pass | match `_Packages(\..*)?` |
| configure the overlay's `sources.list` | `debian:bookworm` also ships a deb822 `sources.list.d/debian.sources`; apt fetched `deb.debian.org` indexes **alongside** the snapshot | remove the base image's sources; assert zero off-pin index files |
| capture each resolution's exit status | `resolve_once ... \|\| die` leaves `$?` holding the compound's status — always 0 when `die` did not fire, so that assertion passed by construction | capture `$?` immediately, hard-fail on non-zero |
| extract `name_version_arch.deb` by regex | apt percent-encodes (`libstdc%2b%2b-12-dev`); the regex truncated names silently | take field 2 of `--print-uris` output |

Two more in my own drafts, caught by the suites: an unguarded `git ls-files`
aborted the whole recording under `pipefail` on a checkout with no `.git`, and the
first collation case asserted something unachievable (dpkg normalises package names
to lowercase, so `Base-Files` is parsed as `base-files`). The sortedness claim is
now the narrower true one and carries a negative control proving `sort -c` can fail,
rather than a locale test that would pass or degrade per machine.

Also found by running the suites in the *declared* environment rather than the
convenient one: stock `debian:bookworm` ships **no python3**, which the recorder
needs to read `third_party/*/manifest.yml`. It now says so explicitly instead of
failing mid-pipeline, and the CI job runs the probe in a separate pristine
container — `--print-uris` omits already-installed packages, and `python3` is
itself in the list under test, so installing it in the same filesystem would have
silently shrunk the measured set.
