# Phase 7.2 Plan 01: pi-gen overlay mechanism + Debian snapshot pin Summary

**Debian now debootstraps and resolves from snapshot `20260915T000000Z` through a git-tracked `overlays/pi-gen/` tree that is re-applied and re-asserted on every build — including cached-pi-gen builds, which is where the naive placement would have silently stopped working — with four distinct loud failure modes, a post-build gate that reads the built rootfs rather than the declaration, and negative controls proving the load-bearing checks can actually fail.**

## Deviations from Plan

### 1. [Rule 2 — missing critical] The plan's own ordering assertion would have reported a false failure

The plan's verify command greps `^[[:space:]]*apply_pigen_overlay`. The natural way to
write an aborting call is `if ! apply_pigen_overlay ...; then`, which that regex does not
match — the check would have printed "apply_pigen_overlay not called at all" and exited 1
against correct code.

**Fixed by changing the code to match the documented assertion**, not by loosening the
assertion:

```bash
apply_pigen_overlay "${PI_GEN_DIR}" "${REPO_ROOT}/overlays/pi-gen" || {
    fail "pi-gen overlay did not apply cleanly — aborting before the build."
    ...
    exit 1
}
```

The call now starts at column 0, so the assertion a reviewer or plan 04 re-runs is the one
that actually guards the design's most emphasised claim. **Commit:** `e0d07f0`.

### 2. [Rule 2 — missing critical] Gate 1 matched its own comment

The plan specifies `grep -q 'snapshot.debian.org/archive/debian/20260915T000000Z'` against
the rootfs `sources.list`. The overlay files carry explanatory header comments naming the
snapshot, and those comments are copied into the rootfs — so that grep would have been
satisfied by a comment even if every active `deb` line were wrong. Exactly the
green-gate-measuring-nothing shape this phase exists to eliminate.

Two changes:

- the gate now matches `^deb[[:space:]]+http://snapshot\.debian\.org/archive/debian/${PIGEN_SNAPSHOT}[[:space:]]`
  — an **active** line, not a substring anywhere in the file;
- the rolling mirror's hostname was removed from the two overlay files that get copied into
  the rootfs, comments included, and `sources.list` now says so in its own header. Gate 3
  greps the rootfs for that literal as evidence nothing resolved off-pin; a mention in a
  comment would have satisfied it on its own text.

**Commits:** `b9b4a2a` (overlay wording), `e0d07f0` (gate). Digests re-recorded.

### 3. [Rule 2 — missing critical] A deb822 `.sources` file would bypass the sources.list gate entirely

Discovered while tracing an unexpected result in the container probe: the `debian:bookworm`
base image ships **no** `/etc/apt/sources.list` at all. Its Debian sources live in
`/etc/apt/sources.list.d/debian.sources` in deb822 format. Writing a pinned
`/etc/apt/sources.list` left the rolling-mirror deb822 file active, and apt happily used
both — which is why the first probe reported 12 snapshot list files *and* 6 rolling-mirror
ones.

That was a probe artifact, not an overlay defect: the real pi-gen rootfs has a classic
`sources.list` and only `raspi.list` under `sources.list.d/`. But it is a live hazard for a
future `PIGEN_REF` that moves to deb822, and the plan's gate 1 read only `sources.list`.

Added a second assertion: **no** non-comment line in `sources.list` *or* anything under
`sources.list.d/` may name the rolling mirror. Verified not to false-positive against the
real rootfs. **Commit:** `e0d07f0`.

### 4. [Addition] Two self-test cases beyond the plan's five

- **`mode-source`** replaces the plan's case 4. The plan asked only that `stat -c %a` on
  `prerun.sh` equals `755` after a successful apply, which a copy would satisfy by
  inheritance. The fixture's overlay source is now deliberately `644`, so the case proves
  the installed mode is driven by the **MANIFEST** — which is what protects against a
  checkout that loses the exec bit, the silent-skip failure the design is built around.
- **`mode-assertion-teeth`** proves failure mode 4 is not dead code, using a MANIFEST mode
  (`0755`) that `stat -c %a` will never render. Without it nothing demonstrates the mode
  comparison can fail at all.
- **`real-manifest`** checks the **shipped** overlay's digests and modes against disk.
  Nothing else catches a hand-edited overlay file whose digest was not re-recorded until a
  build runs, hours in.

**Commit:** `e0d07f0`.

### 5. [Bookkeeping] `overlay_sha256` was `PENDING` in the task-1 commit

The overlay files do not exist at task 1, so their digests cannot. The plan anticipates this
("stale by construction"). The placeholder is the literal `PENDING`, which the applier's
copy-did-not-land check rejects — so the intermediate commit **fails closed** rather than
passing as pinned. Resolved in `b9b4a2a`.
