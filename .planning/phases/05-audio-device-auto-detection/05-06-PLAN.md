<objective>
Implement the AUDIO-04 boot-check sentinel: verify the capture and playback paths actually move audio, retry-then-report on failure, and emit a structured status that the Phase 11 dashboard health view can consume — plus a greppable journal line. The sentinel logic lives in `arlowe_audio.py` as a `--selfcheck` subcommand (RMS check is cleaner in Python with numpy, already a voice dep); the bash `boot-check` calls it and replaces its hardcoded `plughw:2,0` mic probe (the existing `TODO(phase-5)` at boot-check:78).

The verification model is the locked CONTEXT decision: "move audio, no acoustic coupling" — capture records a non-silent buffer, playback emits a tone, the two are checked INDEPENDENTLY (no requiring the mic to hear the speaker). Retry a few times (devices settle after USB enumeration), then start anyway and report (functional-degraded over hard block).

Purpose: Surface audio failures clearly at boot, in a shape Phase 11 reads without re-running probes.
Output: `arlowe_audio --selfcheck`, an updated `boot-check` audio section, and unit tests for the sentinel logic (real-audio assertion is hardware-deferred to 05-07).
</objective>

  <name>Task 1: arlowe_audio --selfcheck — capture RMS + playback tone + JSON status</name>
  <files>runtime/lib/arlowe_audio.py, runtime/lib/tests/test_arlowe_audio_selfcheck.py</files>
  <action>
Add a `selfcheck()` function + `--selfcheck` CLI subcommand to the existing module (built in 05-01). Keep audio I/O isolated behind small, mockable helpers so the orchestration logic is unit-testable without real hardware.

`selfcheck(state_dir=None, retries=3, capture_runner=None, playback_runner=None) -> dict`:
- Resolve capture + playback devices via the existing `resolve_capture`/`resolve_playback`.
- Capture sentinel: record a short buffer (~0.5-1s) on the resolved capture device via `arecord -D <dev> -f S16_LE -r 16000 -c 1 -d 1` to a temp WAV (or stdout), load with numpy/scipy, compute RMS, assert RMS above a low floor ("non-silent"). Use a FORGIVING floor (research P6: plughw resampling can be quiet — do not set the threshold high). Inject the recording step behind `capture_runner` (default = the real arecord helper) so tests pass a fake that returns a known buffer.
- Playback sentinel: emit a short tone to the resolved playback device (`sox -n -t wav - synth 0.3 sine 440 | aplay -D <dev>` or equivalent), checked INDEPENDENTLY — success = the play command exits 0 (no acoustic coupling required, locked decision). Inject behind `playback_runner`.
- Retry: each sentinel retries up to `retries` times with a short sleep between (devices settle post-enumeration), then reports its final pass/fail. Never raise to the caller — always return a status dict.
- Return + persist status shaped for Phase 11 (research §7):
  ```json
  {"check":"audio",
   "capture":{"device":"plughw:1,0","ok":true},
   "playback":{"device":"plughw:0,0","ok":false,"error":"<msg>"},
   "ts":"<iso8601>"}
  ```
  When `state_dir` is provided (default `/var/lib/arlowe/state`), atomically write this JSON to `<state_dir>/audio-selfcheck.json` (temp+rename, mirroring the Phase 4 atomic-write convention). If the dir is unwritable, log and skip the file (do not crash — research P9 flags boot-check's run context as unconfirmed).
- Emit a greppable journal line to stderr with the `[arlowe-audio]` prefix (mirroring the config loader's `[arlowe-config]` convention), e.g. `[arlowe-audio] selfcheck capture=ok playback=FAIL device=...`.
- `--selfcheck` CLI: run `selfcheck()`, print the JSON to stdout, exit 0 if BOTH ok, nonzero (e.g. 1) if either failed — so boot-check can branch on exit code.

`runtime/lib/tests/test_arlowe_audio_selfcheck.py`:
- Test `selfcheck` with injected `capture_runner`/`playback_runner` fakes:
  - capture returns a non-silent buffer + playback exits 0 -> status both ok, JSON written, exit-equivalent success.
  - capture returns a silent (all-zeros) buffer -> capture ok=False with an error, retried `retries` times.
  - playback runner raises/nonzero -> playback ok=False, retried.
  - state_dir = tmp_path -> assert `audio-selfcheck.json` exists with the expected shape; state_dir unwritable (or None) -> no crash.
- No real arecord/aplay/sox invoked in tests.
  </action>
