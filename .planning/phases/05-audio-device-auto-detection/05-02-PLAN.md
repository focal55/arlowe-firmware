<objective>
Wire the Phase 5 audio resolver into the Python runtime so every Python capture/playback surface uses the auto-detected (or owner-overridden) device instead of `plughw:2,0`. This plan owns the single biggest correctness trap in the phase (research P1): `voice_client.py` has TWO independent capture mechanisms — an `arecord` subprocess AND a pyaudio wake-word stream that currently ignores the device string and grabs "first PortAudio input by index." BOTH must point at the same physical card, or the live wake-word mic diverges from STT.

Purpose: Kill the hardcoded device in the Python hot path and guarantee the wake-word mic and the STT-capture mic are the same device.
Output: `voice_client.py`, `tts_sync.py`, and `auto_collect.py` all resolving devices through `arlowe_audio`, with capture and playback split.
</objective>

  <action>
Replace the hardcoded device seam (lines ~48-50) and fix the pyaudio path (lines ~337-353).

1. At the device-string init (currently `RECORD_DEVICE`/`PLAY_DEVICE` both from `ARLOWE_ALSA_DEVICE` defaulting to `plughw:2,0`):
   - `import arlowe_audio` (it is on PYTHONPATH via the unit — `arlowe-voice.service:14` sets `/opt/arlowe/runtime/lib`).
   - Load the Phase 4 config to get override tokens: `from arlowe_config import load; _cfg = load(); _cap_override = _cfg["audio"]["capture_device"]; _play_override = _cfg["audio"]["playback_device"]`.
   - `RECORD_DEVICE = os.environ.get("ARLOWE_ALSA_DEVICE") or arlowe_audio.resolve_capture(_cap_override) or "plughw:2,0"` — keep `ARLOWE_ALSA_DEVICE` as an explicit manual override escape hatch (highest priority), then resolver, then a last-ditch literal so the service never crashes with a None device. SPLIT playback: `PLAY_DEVICE = os.environ.get("ARLOWE_PLAY_DEVICE") or arlowe_audio.resolve_playback(_play_override) or "plughw:2,0"`. (Research P3: stop conflating capture and playback into one env var.)
   - If `resolve_capture` returns None (no mic), log a clear `[arlowe-audio] no capture device found` line to stderr so the journal shows it (locked: degraded-but-running over hard block; the boot-check sentinel in 05-06 is the formal failure surface).

2. Fix the pyaudio wake-word stream (main_loop, ~337-353). Today it loops `get_device_count()` and takes the first device with `maxInputChannels>0`, ignoring `RECORD_DEVICE`. Change it to target the SAME card as `RECORD_DEVICE`:
   - `pa = pyaudio.PyAudio()`
   - `device_index = arlowe_audio.portaudio_index_for_card(RECORD_DEVICE, pa)` — name-substring match against the resolved ALSA card.
   - If `device_index is None`, fall back to the existing "first input-capable device" loop (preserve current behavior as the fallback only), and log `[arlowe-audio] pyaudio could not match ALSA card <RECORD_DEVICE>; using PortAudio default`.
   - Pass that index to `pa.open(... input_device_index=device_index)`.
   This guarantees the always-on wake-word mic and the arecord/STT capture are the same physical device.

Do not refactor unrelated code. Keep the change surgical. Add a one-line WHY comment at the pyaudio fix explaining the name-match (the index namespaces differ between ALSA and PortAudio).
