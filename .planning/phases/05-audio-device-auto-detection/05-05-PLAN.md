  <action>
Create the udev rule. Match the header-comment style of `91-arlowe-gpio-spi.rules` (purpose, why, debounce note). Name `92-` to follow the existing `90-`/`91-` numbering so the install glob (`provision/udev/*.rules`) picks it up with zero script edits (install-arlowe-udev-polkit.sh:42).

Rule requirements (research §4, Pitfall P4):
- Scope strictly to `SUBSYSTEM=="sound"`. Do NOT match broadly.
- Debounce the multi-event storm: a single USB audio plug fires control + pcm-capture + pcm-playback + timer events. Anchor the restart on the control node only — match `KERNEL=="controlC[0-9]*"` so only the one control-device add/remove triggers a restart, not every sub-node. Handle both `ACTION=="add"` and `ACTION=="remove"`.
- Action: `RUN+="/bin/systemctl --no-block restart arlowe-voice.service"`. `--no-block` is mandatory (avoids udev<->systemd deadlock, research §4). udev runs as root so polkit is not consulted (polkit only gates the unprivileged dashboard path) — but the targeted unit is still an `arlowe-*` unit, consistent with the Phase 3 contract.
- Add a comment documenting that this is the v1 mechanism (full restart) and that an in-process reconfigure is a future optimization (research P5: a restart mid-recording aborts an in-flight interaction — acceptable for v1, noted).
- Confirm the systemctl path: prefer `/bin/systemctl` but note in a comment that if the target image uses `/usr/bin/systemctl`, the install/verify step should confirm. (Pi OS has `/bin/systemctl` as a symlink; keep `/bin/systemctl`.)
  </action>
