  <name>Task 1: GET /api/audio/devices — server-side enumeration from /proc/asound</name>
  <files>runtime/dashboard/app/api/audio/devices/route.ts</files>
  <action>
Create the enumeration endpoint. Mirror the SHAPE of `app/api/connectivity/networks/route.ts` (NextResponse, try/catch, structured JSON, console log prefix) but read `/proc/asound` via `fs` instead of shelling a command.

Why fs not shell: the dashboard unit has `PrivateDevices=yes` (research P2) so `arecord -l` may be blocked; `/proc/asound` is procfs and unaffected. Reading procfs via `fs.readFile` also has zero command-injection surface (security requirement).

Implementation:
- `import { readFile, readdir } from 'fs/promises'` and `import { NextResponse } from 'next/server'`.
- Read `/proc/asound/cards` to get index + bracketed id + longname per card.
- For each card N, read `/proc/asound/card{N}/id` (canonical card-id token), and check `readdir('/proc/asound/card{N}')` for `pcm*c` (capture) / `pcm*p` (playback) entries to classify capability. (This mirrors the parsing arlowe_audio.py does in Python — keep the logic equivalent; do NOT shell out to python here, the endpoint must work standalone in the dashboard sandbox.)
- Build friendly names: longname-derived label, e.g. USB cards -> "USB Audio Device (<longname>)", wm8960 substring -> "Whisplay Speaker/Mic (WM8960)", vc4-hdmi -> "HDMI <n>". Fall back to the raw longname.
- Return `{ capture: [{ id, name, index }], playback: [{ id, name, index }] }` — id is the stable card-id token (the value that gets stored), name is the friendly label, index is informational only.
- On any read error (e.g. /proc/asound absent in a non-Pi dev container) return `{ capture: [], playback: [] }` with 200, NOT a 500 — the UI empty-state handles it. Log the error.
- Guard against path traversal: only ever read fixed `/proc/asound/...` paths derived from integer card indices you parsed; never interpolate untrusted input into a path.
  </action>
  <verify>`cd runtime/dashboard && npx tsc --noEmit` passes (or the project's lint/build). On a machine without /proc/asound the route returns `{capture:[],playback:[]}` (can be unit-mocked or reasoned). `grep -n "child_process\|exec(" runtime/dashboard/app/api/audio/devices/route.ts` returns nothing (no shelling).</verify>
  <done>GET endpoint returns capture/playback arrays with id+friendly-name+index, read from /proc/asound via fs, never shells, never 500s on missing procfs.</done>
</task>
