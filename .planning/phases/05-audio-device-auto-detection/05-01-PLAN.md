<task type="auto">
  <name>Task 1: Write arlowe_audio.py — enumeration + card-id resolution + auto-pick</name>
  <files>runtime/lib/arlowe_audio.py</files>
  <action>
Create a stdlib-only module (no pyalsa, no sounddevice) that parses procfs and exposes a clean resolution API. It must NEVER write config and NEVER restart services — pure read + compute.

Required structure:

1. `enumerate_cards(proc_root="/proc/asound") -> list[dict]`
   - Parse `{proc_root}/cards` for index + bracketed card ID + longname.
   - For each card index N, read `{proc_root}/card{N}/id` as the canonical stable card-id token (authoritative over the bracketed name if they differ).
   - Determine capture/playback capability by checking for `{proc_root}/card{N}/pcm*c` (capture) and `{proc_root}/card{N}/pcm*p` (playback) directories. Fall back to parsing `arecord -l` / `aplay -l` ONLY as a cross-check if procfs is ambiguous — but procfs is the source of truth (works under the sandbox; see research §3, §9-P2).
   - Classify each card: `is_usb` (longname/`{proc_root}/card{N}/usbid` indicates USB), `is_wm8960` (id/longname contains `wm8960` substring, case-insensitive — match on substring, NOT a hardcoded index, per research §6), `is_hdmi` (`vc4-hdmi` substring).
   - `proc_root` MUST be a parameter so tests inject fixtures. Make `arecord -l`/`aplay -l` cross-check optional and skippable (a flag or env) so tests run without ALSA installed.

2. `resolve_capture(override_token, cards=None, proc_root="/proc/asound") -> str | None`
   - If `override_token` is a real card-id token (not None, not "auto", strip any `cardid:` prefix if you adopt one) AND a card with that id is present -> return `plughw:{N},0`.
   - Else auto-pick in this order (locked decision): first USB capture card -> else wm8960 capture card -> else None (genuine "no mic" failure — return None, do not raise).
   - Use `plughw` (forgiving resample), never bare `hw` (research §3, P6).

3. `resolve_playback(override_token, cards=None, proc_root="/proc/asound") -> str | None`
   - Override resolution identical to capture.
   - Auto-pick order (Target B, research §6): first USB playback -> wm8960 codec -> HDMI (`vc4-hdmi*`) -> None.
   - NOTE in a module docstring: "Pi 5 has no onboard 3.5mm analog jack; the AUDIO-02/SC2 '3.5mm fallback' is the Whisplay WM8960 codec on this hardware." This documents the SC2 reframe at the code level.

4. Tie-break: when multiple compatible cards in the same class, pick lowest ALSA card index for determinism (locked: Claude's discretion -> deterministic lowest-index).

5. PortAudio bridge helper for the wake-word path (research P1 — the single biggest trap):
   - `portaudio_index_for_card(card_id_or_plughw, pa) -> int | None` that, given a resolved ALSA card and a `pyaudio.PyAudio()` instance, finds the PortAudio input device whose `name` substring-matches the ALSA card longname/id, returning its index. Keep `pyaudio` import lazy/optional (import inside the function, guarded) so the module imports cleanly in CI without pyaudio. Return None if no match (caller falls back to PortAudio default).

6. CLI surface via `if __name__ == "__main__"` / argparse:
   - `python3 -m arlowe_audio --resolve-capture` -> prints resolved capture plughw string (empty + nonzero exit if None).
   - `python3 -m arlowe_audio --resolve-playback` -> prints resolved playback string.
   - `python3 -m arlowe_audio --list` -> prints enumerated cards as JSON (for the boot-check/dashboard cross-check and debugging).
   - These read the override token from the Phase 4 config loader: `from arlowe_config import load; cfg = load(); cfg["audio"]["capture_device"]`. Import lazily inside the CLI handler so unit tests of the pure functions don't require a config file.

Use module-level constants for the substrings (`WM8960_MATCH = "wm8960"`, etc.). No defensive programming for impossible cases; validate only the procfs-shape boundary. Comment only WHY where non-obvious (e.g. why plughw not hw, why substring match for wm8960).
  </action>
