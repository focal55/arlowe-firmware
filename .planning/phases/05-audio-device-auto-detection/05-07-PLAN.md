Sections:

1. **Preconditions** — a Pi with Phase 5 provisioned under `/opt/arlowe`, arlowe-voice/dashboard installed, a USB audio adapter on hand. Note (like phase-4) that arlowe-1 the dev daily-driver does NOT have this layout, so this is the deferred staging/Phase-6/12 procedure.

2. **SC2 REFRAME (read first).** State plainly: the Pi 5 has NO onboard 3.5mm analog jack (research §6 Target B); the AUDIO-02/SC2 "3.5mm fallback" does not describe this hardware. The real output chain is **USB out (preferred) -> Whisplay/WM8960 codec -> HDMI**. Selection matches on the `wm8960` substring, not a fixed index. This section is the authoritative reframe; the verification below tests the wm8960 fallback, not a jack.

3. **SC1 — capture auto-select.** With USB mic plugged: `cat /proc/asound/cards` (confirm the USB card present), `PYTHONPATH=/opt/arlowe/runtime/lib python3 -m arlowe_audio --resolve-capture` -> expect the USB card's plughw. Trigger a wake-word interaction; confirm capture works. Unplug the USB mic, reboot, repeat resolve -> expect fallback to wm8960. Replug, reboot -> expect USB picked up again (no manual config). Also confirm the wake-word pyaudio stream uses the same card (research P1) — check the voice journal for the `Device:` line / the `[arlowe-audio]` pyaudio-match log.

4. **SC2 — output preference + fallback.** With USB speaker plugged: `--resolve-playback` -> USB. Unplug -> wm8960. Confirm a `speak` test plays on the expected card each time.

5. **SC3 — override persists + honored over auto.** Save an override via the dashboard (`POST /api/config` with `audio.capture_device: "<card-id>"`), confirm `/etc/arlowe/config.yml` written atomically, reboot, confirm `--resolve-capture` returns the override even when a different auto-pick would otherwise win. Then test the locked "override absent at boot -> silent fallback to auto": set an override to a card-id that's NOT plugged, reboot, confirm it silently auto-detects instead of failing.

6. **SC4 — sentinel surfaces.** Run `python3 -m arlowe_audio --selfcheck`; confirm `/var/lib/arlowe/state/audio-selfcheck.json` matches the Phase-11 shape and `journalctl | grep '[arlowe-audio]'` shows the line. Force a failure (unplug capture) and confirm capture.ok=false with retry behavior.

7. **Hotplug (beyond-SC1 locked decision).** With the system running, plug/unplug the USB mic; confirm `journalctl -u arlowe-voice` shows exactly ONE restart per event (no storm), and the new device is in use afterward.

8. **Deferred hardware-only unknowns checklist** (from research Open Questions — list each as a confirm-on-hardware item): exact `sound` udev events + correct debounce anchor (`udevadm monitor --subsystem-match=sound`); whether `arecord -l` works under the dashboard `PrivateDevices=yes` (and that the fs-based endpoint is the safe path); boot-check boot-time run-user + `/var/lib/arlowe/state` writability; production WM8960 soundcard name; `/dev/snd/by-id` contents (expect absent); PortAudio<->ALSA name-match correctness for the wake-word stream.

Keep it operational and exact — this is a runbook, not prose.
