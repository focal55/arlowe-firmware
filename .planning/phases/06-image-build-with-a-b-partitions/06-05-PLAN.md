<objective>
Implement the A/B boot selector and the slot-B recovery experience — the two halves of the same mechanism (per 06-RESEARCH these are tightly coupled). The persistent default is the boot `root=` (ADR-0005, plan 06-01): config.txt sets tryboot_a_b=1, the default cmdline points root= at slot A's PARTUUID, and the one-shot tryboot.txt path is reserved for Phase 9. `arlowe-ab` flips the persistent default by rewriting root= and rebooting (the seam Phase 9 OTA reuses — treat it as the primitive, not a throwaway). Slot B is a minimal recovery rootfs that proves the hardware is alive (Whisplay recovery face), surfaces state on serial/journal, and resets the default to A so a plain reboot self-heals.

**Shared-model design (REVISED 2026-06-13, ADR-0004):** the selector is largely unaffected — it still swaps only the rootfs `root=` on the shared /boot. Both slot A and slot B mount the SAME shared read-only models partition at /opt/arlowe/models (the mount is identical; the selector does not touch it). The recovery stub is minimal and does NOT depend on the models partition to do its job (show face + reset default), but its fstab carries the same shared models mount entry for consistency (harmless if the models partition is absent/unused in recovery — mark it nofail).

Wires into plan 06-04: build-image.sh's extension point calls boot-config.sh (lay tryboot config into the FAT) and recovery-stub.sh (write the recovery rootfs into slot B p3), using the PARTUUIDs partition-image.sh exported (including the shared models PARTUUID for the slot-B fstab).

Purpose: This is what makes PART-02/03/06 and SC3 true — manual A->B flip + a recovery that looks intentional, not bricked. The flip primitive is the Phase 9 OTA foundation.
Output: boot config + recovery stub builder libs, arlowe-ab CLI, recovery service/script, A/B + recovery docs.
</objective>
