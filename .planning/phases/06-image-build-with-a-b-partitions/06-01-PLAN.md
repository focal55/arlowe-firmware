<objective>
Reconcile the Phase 6 requirements/ROADMAP text with two design decisions that contradict it, BEFORE any build work happens. These are owner-facing spec changes (partition layout/sizing + boot-selector mechanism), so they are visible, reviewable deliverables — not silent build-time decisions.

Two reconciliations:
1. **Single shared models partition + 5-partition layout (REVISED 2026-06-13).** The owner reversed the earlier "models baked into each rootfs slot" decision. Models (Qwen/Axera, Whisper, Piper) now live ONCE on a shared read-only `models` partition mounted at `/opt/arlowe/models` in BOTH slots. Slots A and B remain full per-slot rootfs (OS + runtime, equal-sized) but WITHOUT the bulky models, so each shrinks to ~2-3 GB. This adds a fifth partition and FLIPS the grow-to-fill target: the `models` partition grows to fill the card (maximizing model headroom), while `/var/lib/arlowe` owner-state becomes a FIXED modest partition (~2-4 GB; PART-05 needs ~1 GB). Models must NOT live on owner-state — factory reset (PAIR-07) wipes it and it is owner-writable. **Sizing flips:** 16 GB is now VIABLE (one ~6 GB model set + ~5.5 GB fixed overhead fits a 16 GB card's ~14.8 GB usable, leaving ~9 GB for models); 32 GB is RECOMMENDED for larger-model headroom, not MANDATED. IMAGE-04's "≤16 GB target" is achievable again. The research GATE 1 "16 GB impossible → 32 GB floor" verdict is SUPERSEDED by this shared-model design.
2. **tryboot root= swap, not U-Boot/active.txt.** PART-02/SC3 say the selector "reads a flag (U-Boot env or /boot/active.txt)". The locked single-shared-/boot tryboot design instead flips the persistent default by editing the boot `root=` in `config.txt`/`cmdline.txt`. The one-shot `tryboot.txt` path is reserved for Phase 9 OTA trial-boot. (UNAFFECTED by the model-store change — this reconciliation stands as before.)

Purpose: Downstream plans build to a 5-partition shared-model layout and a root=-swap selector; the docs must agree before that, or the phase ships against a stale spec.
Output: Two ADRs + amended REQUIREMENTS.md (IMAGE-02/03/04, PART-01/02/03/05) + amended ROADMAP.md Phase 6 Goal/SC1/SC2/SC3/SC5.
</objective>

- Qwen2.5-7B-Instruct GPTQ-Int4 (AX650): ~5.51 GB

Decision: A SINGLE shared, read-only, root-owned `models` partition mounted at `/opt/arlowe/models` in BOTH slot A and slot B. System A and B remain full per-slot rootfs (OS + runtime, equal-sized — locked decision unchanged) but model-free. The `models` partition is the grow-to-fill partition (consumes remaining card space on first boot → maximum headroom for larger models via future model-OTA). `/var/lib/arlowe` owner-state becomes a FIXED modest partition (~2-4 GB; must NOT hold models — factory reset wipes it and it is owner-writable). In v1 the models partition is read-only; a v2 model-OTA agent can remount rw.

Record the accepted tradeoff explicitly: a future OS slot (v2 OS-OTA) SHARES the same models partition — a new OS needing different model formats cannot swap models atomically with the OS slot. This is acceptable: Phase 9 app-OTA touches `runtime/` only (never models), and model-OTA is a v2 concern. No v1 cost.

Sizing: 16 GB is VIABLE — one ~6 GB model set + ~5.5 GB fixed overhead (boot + slot A + recovery B + owner-state) fits a 16 GB card's ~14.8 GB usable, leaving ~9 GB for the models partition. 32 GB is RECOMMENDED (gives ~25 GB model headroom) but NOT mandated. State that IMAGE-04's ≤16 GB target is achievable again. Concrete starting sizing (512 MB /boot, ~3 GB slot A, ~3 GB slot B, ~2-4 GB owner-state, remainder = models grow-to-fill) is a MEASURE-THEN-SET starting point that plan 06-04 finalizes from real `du` numbers (model-free slot rootfs measured separately from the models set).

Do NOT use defensive hedging — state the decision directly. This is the canonical owner-facing record of the shared-model architecture decision.

  <files>docs/architecture/0005-ab-selector-tryboot-root-swap.md</files>
  <action>
Write an ADR recording the boot-selector mechanism, correcting PART-02/SC3. (This ADR is UNAFFECTED by the shared-model design change — the selector still swaps root= on the shared /boot.)

Context: PART-02/SC3 wording ("U-Boot env or /boot/active.txt") is wrong for the locked Pi-native tryboot, single-shared-/boot design. Summarize 06-RESEARCH.md GATE 2: Pi 5 firmware A/B has two styles — partition-level (rejected; needs two FAT boot partitions) and file-level within one boot partition (`tryboot_a_b=1`, firmware loads `tryboot.txt` instead of `config.txt` on the one-shot path). `reboot "0 tryboot"` is ONE-SHOT and reverts on power-cycle, so a persistent default flip cannot use it.

Decision: The persistent A/B default is the boot `root=` in the shared `/boot/firmware` config (`cmdline.txt` / inline `cmdline=` in `config.txt`). `arlowe-ab` flips the persistent default by rewriting `root=` to point at the target slot's PARTUUID, then rebooting. `tryboot_a_b=1` + `tryboot.txt` + `reboot "0 tryboot"` are RESERVED for the Phase 9 OTA one-shot trial-boot path — not used for the v1 persistent flip. No U-Boot, no custom initramfs, no `active.txt` flag file.

Consequences: `arlowe-ab` (plan 06-05) owns the `root=` rewrite as the seam Phase 9 reuses. The slot-B recovery stub (plan 06-05) self-heals by rewriting `root=` back to slot A. Note the Pi-5 freeze-on-corrupt-kernel caveat (power-cycle recovers) for the recovery framing. Both slots mount the same shared `models` partition (ADR-0004); the selector swaps only the rootfs `root=`, not the models mount, which is identical for A and B.
