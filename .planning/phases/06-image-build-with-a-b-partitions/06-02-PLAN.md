<objective>
Establish the SHA-pinned fetch/verify pattern for the model artifacts and the WhisPlay driver — the inputs the image stages onto the shared models partition. These are large binaries with unresolved redistribution rights, so they follow the existing axcl "Strategy C" pattern: pinned by SHA in a manifest, url null, never committed, user/CI supplies the file out-of-band, and `verify-third-party.sh` gates the build.

This plan is UNAFFECTED in substance by the shared-model design change (ADR-0004): the artifacts are pinned/verified the SAME way whether they land per-slot or on a single shared partition. The only difference is WHERE 06-03/06-04 place them (a single shared models partition, not duplicated per slot) — the manifest just pins ONE copy of each artifact. Do NOT assume per-slot duplication anywhere in the manifest or verify logic.

This plan does NOT build an image. It produces the manifest + verify gate + the Whisper model decision, so plan 06-03 (chroot provisioning) has a verified set of artifacts to assemble into the shared models tree.

Purpose: The shared models partition needs a single, pinned, verified copy of each model; without a pinned, verified source the build is non-reproducible and may silently ship the wrong/corrupt model. The axcl deb already proves this pattern works.
Output: third_party/models/manifest.yml + INSTALL.md, extended verify-third-party.sh, ADR-0006 (Whisper choice), whisplay-driver INSTALL.md.
</objective>
