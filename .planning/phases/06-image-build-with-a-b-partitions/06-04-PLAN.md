<objective>
Produce the real 5-partition shared-model A/B `.img` via the build-blank-then-rsync approach, with measure-then-set sizing and a MODELS-partition grow-to-fill. This is the orchestration spine: verify deps -> pi-gen builds one model-free rootfs + a separate models tree -> measure both -> create a blank sized image -> rsync rootfs into slot A + seed the shared models partition -> (slot B recovery stub lands in plan 06-05) -> sanitize-scan -> emit. The shared MODELS partition grows on first boot via a resize hook wired into plan 06-03's armed first-boot service; owner-state is now FIXED.

**Shared-model design (REVISED 2026-06-13, ADR-0004):** models live ONCE on a shared read-only `models` partition mounted at /opt/arlowe/models in both slots — NOT baked per-slot. This adds a fifth partition and FLIPS the grow-to-fill target from owner-state (old design) to the models partition (maximizes headroom for larger models). Slots A and B are EQUAL size and model-free (true-swap symmetry); B's recovery-stub content is plan 06-05. Sizing is MEASURE-THEN-SET — du the model-free rootfs, add 25%, that is the slot size; du the models tree (06-03's standalone tree) to seed the models partition; the ADR-0004 numbers (512 MB boot, ~3 GB slots, ~2-4 GB owner-state, models = remainder) are starting points to be replaced by measured values. 16 GB is viable, 32 GB recommended.

Per the locked decisions and 06-RESEARCH: build ONE rootfs, then a custom post-process repartitions (pi-gen has no native multi-partition A/B). 

Purpose: This is the deliverable that makes IMAGE-01/04/05 and PART-01/04/05 true. Measure-then-set is the locked sizing discipline; getting it wrong silently drops a slot, starves owner-state, or under-sizes the models partition.
Output: scripts/build-image.sh, scripts/lib/partition-image.sh, models grow script, partition docs.

ATOMIC-PR NOTE: the 5-partition + separate-models-rsync + models-grow work is incremental over the original 4-partition plan and should stay under the <600-net-line cap as one plan. If the implementer finds the models-partition seeding + 5-part layout pushes partition-image.sh materially over budget, split Task 2 into "5-partition layout" and "models-partition seed + fstab" as 06-04a/06-04b (same wave 2, same depends_on) and note it — do NOT silently exceed the cap.
</objective>

<task type="auto">
  <name>Task 2: 5-partition build-blank-then-rsync layout library (boot, A, B, models, owner-state)</name>
  <files>scripts/lib/partition-image.sh</files>
  <action>
Create scripts/lib/partition-image.sh implementing the build-blank-then-rsync approach (06-RESEARCH "A/B partition layout") for the FIVE-partition shared-model layout (ADR-0004):

1. Create a blank sparse .img of $CARD_SIZE_GB.
2. parted/sgdisk: 5 partitions —
   p1 /boot FAT32 (512 MB, firmware + both slots' kernels + tryboot configs),
   p2 system A ext4 (= measured model-free slot size),
   p3 system B ext4 (EQUAL to p2 — true-swap symmetry; content written by plan 06-05),
   p4 shared MODELS ext4 (sized = models seed + grows-to-fill on first boot; this is the grow-to-fill partition),
   p5 /var/lib/arlowe ext4 (FIXED, ~2-4 GB owner-state — sized for PART-05 needs, NOT grow-to-fill).
   PARTITION ORDER MATTERS: the grow-to-fill partition (p4 models) must be positioned so it can extend to the end of the disk. Place the FIXED owner-state (p5) and models (p4) such that the models partition is the LAST growable partition before free space — recommended order is boot, A, B, owner-state, models (models last so growpart extends it to the disk end). If you keep models as p4, document how growpart targets it; the cleanest layout puts the grow-to-fill partition last. Pick one, justify in a comment, and keep the partition NUMBERS referenced consistently everywhere (fstab, grow script, docs).
3. losetup -P the image; mkfs.vfat boot; mkfs.ext4 A/B; mkfs.ext4 models; mkfs.ext4 owner-state (noatime is a mount option, set in fstab not mkfs).
4. rsync -aHAX the pi-gen MODEL-FREE rootfs into slot A. Seed the shared models partition by rsyncing the models staging tree ($ARLOWE_MODELS_STAGE from 06-03) into the models partition. Copy boot files into the FAT.
5. Write /etc/fstab in slot A (and provide the same for B in 06-05): mount /boot/firmware (boot) and /var/lib/arlowe (owner-state, by PARTUUID, noatime) AND the shared models partition READ-ONLY at /opt/arlowe/models (by PARTUUID, ro,noatime). Substitute the real models PARTUUID into the placeholder that 06-03's chroot fstab entry left. Do NOT put A/B in fstab as auto-mounts of each other; the active root is selected by boot root= (plan 06-05). The models mount is IDENTICAL in both slots.
6. Export the PARTUUIDs of ALL FIVE partitions (functions/vars) so plan 06-05's tryboot config + arlowe-ab can reference slot A/B PARTUUIDs, and so the models PARTUUID is available for the fstab substitution + the grow script.
7. Provide a parameterizable function signature so build-image.sh and 06-05 both call it cleanly.

Note this requires loop devices + root (the reason the Mac is unsupported — document in the header). Keep shellcheck-clean.
