<objective>
Produce the real 4-partition A/B `.img` via the build-blank-then-rsync approach, with measure-then-set sizing and owner-state grow-to-fill. This is the orchestration spine: verify deps -> pi-gen builds one rootfs -> measure it -> create a blank sized image -> rsync rootfs into slot A -> (slot B recovery stub lands in plan 06-05) -> sanitize-scan -> emit. Owner-state grows on first boot via a resize hook wired into plan 06-03's armed first-boot service.

Per the locked decisions and 06-RESEARCH: build ONE rootfs, then a custom post-process repartitions (pi-gen has no native 4-partition A/B). Slots A and B are EQUAL size (true-swap symmetry); B's recovery-stub content is plan 06-05. Sizing is MEASURE-THEN-SET — du the rootfs, add 25%, that is the slot size; the ADR-0004 numbers (512 MB boot, ~13 GB slots) are starting points to be replaced by the measured value.

Purpose: This is the deliverable that makes IMAGE-01/04/05 and PART-01/04/05 true. Measure-then-set is the locked sizing discipline; getting it wrong silently drops a slot or starves owner-state.
Output: scripts/build-image.sh, scripts/lib/partition-image.sh, owner-state grow script, partition docs.
</objective>

<task type="auto">
  <name>Task 2: 4-partition build-blank-then-rsync layout library</name>
  <files>scripts/lib/partition-image.sh</files>
  <action>
Create scripts/lib/partition-image.sh implementing the build-blank-then-rsync approach (06-RESEARCH "A/B partition layout"):

1. Create a blank sparse .img of $CARD_SIZE_GB.
2. parted/sgdisk: 4 partitions —
   p1 /boot FAT32 (512 MB, firmware + both slots' kernels + tryboot configs),
   p2 system A ext4 (= measured slot size),
   p3 system B ext4 (EQUAL to p2 — true-swap symmetry; content written by plan 06-05),
   p4 /var/lib/arlowe ext4 (remaining space).
3. losetup -P the image; mkfs.vfat p1; mkfs.ext4 p2/p3; mkfs.ext4 p4 (noatime is a mount option, set in fstab not mkfs).
4. rsync -aHAX the pi-gen rootfs into slot A (p2). Copy boot files into the FAT (p1).
5. Write /etc/fstab in slot A (and provide the same for B in 06-05): mount /boot/firmware (p1) and /var/lib/arlowe (p4, by PARTUUID, noatime). Do NOT put A/B in fstab as auto-mounts of each other; the active root is selected by boot root= (plan 06-05).
6. Export the PARTUUIDs of all four partitions (functions/vars) so plan 06-05's tryboot config + arlowe-ab can reference slot A/B PARTUUIDs.
7. Provide a parameterizable function signature so build-image.sh and 06-05 both call it cleanly.

Note this requires loop devices + root (the reason the Mac is unsupported — document in the header). Keep shellcheck-clean.
  </action>
  <verify>bash -n scripts/lib/partition-image.sh; shellcheck scripts/lib/partition-image.sh || true; grep -q "mkfs.ext4" scripts/lib/partition-image.sh; grep -q "rsync" scripts/lib/partition-image.sh; grep -qi "PARTUUID" scripts/lib/partition-image.sh</verify>
  <done>partition-image.sh creates a 4-partition blank image with equal-sized A/B, mkfs's each, rsyncs rootfs into A, writes fstab (boot + owner-state by PARTUUID noatime), and exports PARTUUIDs for the boot-selector plan.</done>
