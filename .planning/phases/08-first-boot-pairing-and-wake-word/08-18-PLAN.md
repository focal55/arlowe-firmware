<execution_notes>
- `identity.json` lives in the identity store; read `certificate_id`, `thing_name`, `device_id` before the wipe. No `certificate_id` → `skipped`, no network call.
- **Shared resolver (B2).** `runtime/lib/arlowe_broker.py`: `resolve_broker(broker_file, config_url, ca_dir)`. If `broker_file` exists: parse `{"url", "ca_bundle_pem"}`, reject a non-https URL (return None, log the reason), write the PEM to `<ca_dir>/broker-ca.pem` at 0600 when present, return `(url, path)`. Else if `config_url` is non-empty → `(config_url, None)`. Else None. Log only "broker source: file|config|none", never the file's contents. 08-23 imports this same function; it does not get its own copy.
- Revoke runs as root here; `arlowe-identity` reads `device.key` fine as root. Resolve with `broker_file=$ARLOWE_BROKER_FILE` (default `/boot/firmware/arlowe-broker.json`, `ARLOWE_ROOT`-prefixed in tests), `config_url=identity.provisioning_url` from the still-present `config.yml` (step 3 precedes the commit point at step 4), and `ca_dir=tempfile.mkdtemp()` (0700, removed in a `finally`). Run `arlowe-identity revoke --json --ca-broker-url <url>` with `ARLOWE_BROKER_CA_BUNDLE=<ca_path>` in the env when a CA was returned. None → record the orphan with reason `no_broker_url`.
- Template unit: `ExecStart=/usr/bin/python3 /opt/arlowe/runtime/cli/factory-reset --trigger %i`, `Environment=ARLOWE_BROKER_FILE=/boot/firmware/arlowe-broker.json`, `Type=oneshot`, root, no `[Install]`, Use `ProtectSystem=yes` (read-only `/usr` and `/boot`), not `strict` or `full`: the wipe writes `/etc/arlowe`, `/etc/hosts`, `/var/lib/arlowe`, `/var/lib/NetworkManager` and the journal, and `full` would make `/etc` read-only. Say why in a comment. `RestrictAddressFamilies=AF_UNIX AF_INET AF_INET6` (the revoke call). The helper validates `%i`.
- Resume unit: `ConditionPathExists=/var/lib/arlowe/reset-ledger/in-progress`, `ExecStart=… --resume`, the same `ARLOWE_BROKER_FILE`, `RequiresMountsFor=/var/lib/arlowe`, `After=local-fs.target NetworkManager.service`, `Before=arlowe-pair.service arlowe-dashboard.service arlowe-face.service arlowe-voice.service qwen-api.service qwen-tokenizer.service whisper-stt.service`, `WantedBy=multi-user.target`. A resume never re-attempts the revoke once the marker's step is past it; before it, it tries once.
- polkit: the unit names start with `arlowe-`, so `50-arlowe-systemctl.rules` already allows `arlowe` to start `arlowe-factory-reset@dashboard.service`. Assert it in the shell test by reading the rule's prefix logic, not by running polkit.
