- Order inside `Committer.__call__(form, provisioned)`:
  1. `write_owner_credential(state_dir, password)` and `write_session_key(state_dir)` (state dir `/var/lib/arlowe/dashboard`, overridable). Overwrite any previous attempt's files.
  2. Write `/run/arlowe-pair/commit-request.json` `{"display_name"}` and run `systemctl start arlowe-pair-commit.service`; non-zero → raise (the flow shows `setup_failed`).
  3. Build the overlay: `device: {hostname: <slug>, display_name}`, `owner: {paired_at}`, `network: {wifi_label: <ssid truncated to 32 bytes>}`, `identity`: every key of the defaults' `identity` block with `provisioning_url` set to the broker URL used (shallow merge replaces the block, so all four required keys must be present). Never put a password, PSK or claim code in it.
  4. Write `config.yml.tmp` in `/etc/arlowe` (0640), run `python3 -m arlowe_config_validate` with `ARLOWE_CONFIG_PATH=<tmp>`, exit 0 required; fsync the file, `os.replace`, fsync the directory. **Commit point.**
  `__call__` returns after the commit point. It does not start anything.
- `Committer.start_runtime()`: `systemctl start --no-block arlowe-face.service arlowe-voice.service arlowe-dashboard.service qwen-tokenizer.service qwen-api.service whisper-stt.service`, returning the exit code (non-zero is logged by the caller; the unit is paired regardless and the six start on the next boot). There is no `Conflicts=` between `arlowe-pair` and `arlowe-face` (it would cancel the face's start job on every paired boot); 08-23 calls this after drawing the paired screen, holding it and calling `board.cleanup()`, then exits 0.
- Paths (`/etc/arlowe`, `/run/arlowe-pair`, the state dir) and the `systemctl` binary are constructor arguments so tests use a temp root and a shim.
- Argon2: `argon2.PasswordHasher(time_cost=3, memory_cost=65536, parallelism=4, hash_len=32, salt_len=16, type=Type.ID)`.

    - Credential file is 0600 JSON `{hash, created_at}`; `hash` starts with `$argon2id$v=19$m=65536,t=3,p=4$` and verifies the password with `argon2.PasswordHasher().verify`; the plaintext appears in no file under the temp root.
    - Session key file is exactly 32 bytes, 0600, and differs between two calls.
    - Happy path: the shim's call log shows `start arlowe-pair-commit.service` before the config exists, and nothing else: `__call__` starts none of the six.
    - `start_runtime()` issues exactly one `start --no-block` naming all six and returns the shim's exit code.
    - The written config validates (run the validator independently in the test) and has the fields in the spec; the identity block has all four keys.
    - Hostname helper fails → raises; no `config.yml`; the six not started.
    - Validator fails (inject a schema that rejects the overlay) → raises; no `config.yml`; tmp file removed.
    - An existing `config.yml.tmp` from a crash is overwritten, not appended.
    - A 40-byte UTF-8 SSID is truncated to ≤ 32 bytes on a character boundary for `wifi_label`.
    - The config file mode is 0640.
    - No secret in caplog.
  </behavior>
  <implementation>`Committer(paths, runner, clock)` is callable with the flow's `commit(form, provisioned)` signature from 08-13.</implementation>
