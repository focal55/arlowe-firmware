<execution_notes>
- Collaborators: `net` (the 08-07 NetMan interface), `display` (`show(screen)`; a fake records calls; 08-11's `Screen` constructors are not imported here, pass kind strings so this plan does not depend on 08-11), `identity` (callable `(broker_url, ca_bundle_path, claim_code) -> (exit_code, json_dict)`), `commit` (callable `(form, provisioned) -> None`, raises on failure), `clock`, `ntp_synced` (callable; 08-23 supplies the production one), `on_paired` (callable `(provisioned) -> None`, default no-op; 08-23 uses it to start the paired hold), and `session` (`ssid`, `psk`). `net.join` and `JoinError` come from 08-07/08-07b's interface; this plan fakes `net`, so it does not wait for 08-07b.
- The default identity runner (also in flow.py, tested with a shim script) runs `["arlowe-identity", "provision", "--json", "--ca-broker-url", url]` with `env={**os.environ, "ARLOWE_OWNER_TOKEN": code, "ARLOWE_BROKER_CA_BUNDLE": ca}` when a CA is given, 60 s timeout; a timeout maps to `server_unreachable`.
- Mapping (N6, ADR-0011): exit 4 with `http_status` null → `server_unreachable`; exit 3 with 401 → `claim_rejected`; exit 3 other status, exit 4 with a status ≥ 500, or exit 5 → `cert_failed`; a missing broker URL → `not_configured` without calling identity.
- Wait about 2 s after the portal's acknowledgement before `ap_down` (the portal calls `submit` on a thread after flushing; the wait is inside the flow, injectable).
- A second submit while not in WAITING/ERROR is refused (single flight).
- Commit failure (the hostname helper or the config write raised) → ERROR/`setup_failed`, the AP restored, the saved profile deleted. The unit is not paired, because `config.yml` is the last write.
- A retry after `setup_failed` must not request a second certificate: before provisioning, the default runner calls `arlowe-identity status --json`, and if a certificate is already stored it returns that metadata as the provision result. Test it with the shim.
</execution_notes>

<feature>
  <name>Pairing flow</name>
  <files>runtime/pair/flow.py, runtime/pair/tests/test_flow.py</files>
  <behavior>
    - Happy path: display receives connecting → provisioning → committing → paired in order; `commit` called once with the form and identity's JSON; final state PAIRED; `net.ap_up` not called again; `on_paired` called exactly once, after `commit` returned; `display.close` never called by the flow.
    - Wrong PSK (`JoinError(wifi_rejected)`) → ERROR/wifi_rejected; `ap_up(session.ssid, session.psk)` called; `wifi_profiles()` holds no profile other than the setup AP afterwards.
    - Network absent → wifi_not_found.
    - Identity exit 4, status null → server_unreachable; the saved profile for the home SSID is deleted and the AP restored.
    - Identity exit 3, 401 → claim_rejected. Exit 3, 400 → cert_failed. Exit 4, 502 → cert_failed. Exit 5 → cert_failed.
    - No broker URL → not_configured, identity never called.
    - NTP not synced: provision waits until synced or 30 s (fake clock), then proceeds.
    - Resubmit after an error with blank secret fields reuses the held values.
    - Commit raises → setup_failed, AP restored, no saved profile.
    - Concurrent submit → refused.
    - The identity runner's argv never contains the claim code; its env does.
    - caplog contains none of the PSK, dashboard password, claim code or session password.
  </behavior>
  <implementation>A plain class with a lock; `status()` returns a snapshot for the portal.</implementation>
</feature>
