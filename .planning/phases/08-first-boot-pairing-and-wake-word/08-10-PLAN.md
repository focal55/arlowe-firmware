- The revoke hook is a function `revoke_or_record(ctx) -> "ok"|"failed"|"skipped"`, returning `"skipped"` in this plan. Its call site is between "stop" and "commit".
- Never log file contents.

<feature>
  <name>Factory reset engine</name>
  <files>runtime/cli/factory-reset, tests/phase-8/test_factory_reset.py</files>
  <behavior>
    - Full run on a populated fixture root: config.yml gone; identity shim called with `reset --force`; nmcli shim deleted every UUID whose type is `802-11-wireless` and none of type `ethernet`; `var/lib/NetworkManager/{seen-bssids,timestamps,*.lease}` gone; the six state directories exist and are empty except for the recreated skeleton; journalctl shim called with `--rotate` then `--vacuum-time=1s`; hostnamectl shim called with `set-hostname arlowe`; `/etc/hosts` has `127.0.1.1\tarlowe`; `resets.log` gained `{"at", "trigger": "dashboard", "revoke": "skipped"}`; marker gone; `systemctl reboot` called unless `--no-reboot`.
    - Survivors: `reset-ledger/`, `opt/arlowe/models/marker`, `var/lib/arlowe/.firstboot-done`, `.models-grow-done`.
    - Order: the systemctl stop call precedes the config removal, which precedes every wipe (assert from the shims' shared call log).
    - Resume: for each step N, a run killed after step N (inject `ARLOWE_RESET_FAIL_AFTER=N`) followed by `--resume` yields the same end state as a clean run.
    - `--resume` with no marker exits 0 and does nothing.
    - `--trigger` outside {dashboard, button} → exit 2.
  </behavior>
  <implementation>A list of `(name, fn)` steps and a loop that records the index after each. The kill-injection env var raises after the named step; say in the docstring it exists for the resume test.</implementation>
</feature>
