<execution_notes>
- The request contract is in 08-06's execution notes. Canonical bytes: `json.dumps({"certificate_id", "device_id", "issued_at"}, sort_keys=True, separators=(",", ":")).encode()`; signature base64 DER ECDSA-SHA256.
- Verify with the public key from `iot.describe_certificate(certificateId=…)["certificateDescription"]["certificatePem"]`, then check `iot.list_principal_things(principal=<arn>)` contains `device_id`. With AWS, the ARN comes from `describe_certificate` as well.
- Freshness: |now − issued_at| ≤ 300 s. A replayed request within the window re-revokes an already revoked certificate, which is harmless; say so in a comment.
- Already `REVOKED` → 200 (idempotent), and still release.
- The revoke endpoint takes no bearer token: possession of the device key is the authorization.
- Confidence MEDIUM on the AWS half (no AWS call in `scripts/pki/` has ever run; 07-09 parked). 08-28 exercises it against real IoT.
</execution_notes>

<feature>
  <name>Broker revoke endpoint</name>
  <files>scripts/pki/broker.py, scripts/pki/tests/test_broker_revoke.py</files>
  <behavior>
    - Issue a certificate through the stub with a minted code (bound), then a correctly signed revoke → 200 `{"revoked": true, "certificate_id"}`; stub status `REVOKED`; code back to `unused`.
    - Same request again → 200; still revoked.
    - Signature by a different key → 401; status unchanged; code still bound.
    - `issued_at` 301 s old, and 301 s in the future → 401.
    - `device_id` not attached to the certificate → 401.
    - Unknown `certificate_id` (stub raises ResourceNotFound) → 401.
    - Missing field or non-JSON → 400.
    - The device's signer is compatible: one case signs with `arlowe_pki.sign_payload` (08-06) and the handler accepts it. Import only `arlowe_pki` (it needs `cryptography`, which the `pki-broker` job has); `arlowe_cloud` needs `requests`, which that job does not install.
  </behavior>
  <implementation>`handle_revoke_request(body, iot, store, now)` returns `(status, dict)`, mirroring `handle_certificate_request`.</implementation>
</feature>
