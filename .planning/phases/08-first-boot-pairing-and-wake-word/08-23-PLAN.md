<execution_notes>
- `build_app(net, display, portal_factory, flow_factory, committer, clock, broker_source, device_id_reader, bind_addr, hold_s)`; `__main__` supplies the real ones and `ThreadingHTTPServer` on `10.42.0.1:80` (the unit grants `CAP_NET_BIND_SERVICE`). Bind **after** the first `ap_up`, because the address exists only while the AP is up; keep the same server across AP down/up (a Linux socket bound to a local address keeps listening while the address is removed and re-added; MEDIUM confidence, and 08-27b's SC3 rejoin and idle-restart steps prove it; if they fail, rebind on each `ap_up` in a plan-sized fix). Tests bind `127.0.0.1:0`. Never bind `0.0.0.0`: a wired uplink would expose the portal to the LAN.
- **Broker:** `broker_source` defaults to `functools.partial(arlowe_broker.resolve_broker, os.environ["ARLOWE_BROKER_FILE"], <identity.provisioning_url>, "/run/arlowe-pair")`, called at each submission so a file placed after boot is seen. Do not write a second resolver.
- **NTP:** production `ntp_synced` runs `["timedatectl", "show", "-p", "NTPSynchronized", "--value"]` and returns `stdout.strip() == "yes"`; any error returns False (the flow's 30 s cap still applies).
- **Paired handoff (B1/M2).** The flow's `on_paired` sets an event. `run()` then: draws paired (URL `http://<slug>.local:3000` and the IP), waits up to `hold_s` (30, from `ARLOWE_PAIR_HOLD_S`) or until a button press, stops the portal and the idle timer, calls `display.close()` (which calls `board.cleanup()`), calls `committer.start_runtime()` and logs a non-zero result, and returns 0. `__main__` exits with that code. `Restart=on-failure` does not restart an exit 0, and `config.yml` now makes the unit's condition false anyway. A power cut during the hold is safe: the config is already committed.
- Device id: `arlowe_identity.DEVICE_ID_PATH`. Missing → show an error screen "Device identity missing" (use `ErrorKind.setup_failed`'s screen with that detail line) and keep running so the journal and the screen say why; do not exit (Restart= would loop).
- **Stale profile sweep (W1).** First thing in `run()`, before `radio_on()` and the scan: `for u in net.wifi_profiles(): net.delete_profile(u)`. This is safe only because the unit's `ConditionPathExists=!/etc/arlowe/config.yml` guarantees the unit is unpaired, and ADR-0011's invariant is that an unpaired unit has no saved Wi-Fi profile; say so in a one-line comment. It covers a SIGKILL or power cut mid-join (the saved join profile, holding the owner's PSK, would otherwise autoconnect forever) and a surviving in-memory `arlowe-setup` profile after a daemon kill. Wired profiles are untouched (`wifi_profiles()` filters on `802-11-wireless`).
- Idle timeout 30 min (ADR-0011), counted from the AP coming up and reset by every submission; it does not fire while the flow is past WAITING. Timer runs off the injected clock.
- The portal and display reuse `session.ssid`/`session.psk`; a new session replaces both, and the QR updates.
</execution_notes>
