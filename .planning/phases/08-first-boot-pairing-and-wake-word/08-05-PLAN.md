<feature>
  <name>Claim-code store</name>
  <files>scripts/pki/claim_codes.py, scripts/pki/tests/test_claim_codes.py</files>
  <behavior>
    - `normalize("abcde-fghjk mnpqr-stvwx")` → `"ABCDEFGHJKMNPQRSTVWX"`; a code that is not 20 Crockford characters after normalizing raises `ValueError`. Crockford aliases `I,L→1` and `O→0` are applied.
    - `ClaimStore(path).mint(note)` returns a new 20-char code from `secrets`; the store gains an `unused` entry keyed by its hash.
    - `redeem(code, device_id)`: `unused` → `bound` to device_id, returns True; `bound` to the same id → True, unchanged; `bound` to another id, `revoked`, or unknown → False. Callers cannot tell those three apart.
    - `release(code)`: `bound` → `unused` with `device_id` cleared. `release_device(device_id)`: releases every code bound to that id, returns the count.
    - `revoke(code)`: any state → `revoked`.
    - Every mutation takes `fcntl.flock(LOCK_EX)` on `<path>.lock`, re-reads the file, writes `<path>.tmp`, fsyncs and `os.replace`s. A missing store file on load raises `FileNotFoundError` (the broker refuses to start on it).
    - CLI: `claim_codes.py --store PATH mint [--note N]`, `revoke CODE`, `release CODE`, `list` (hash prefix, state, device_id prefix, dates; never a code).
  </behavior>
  <implementation>Keep the redeem decision a pure function over one entry so the broker can call it under the same lock.</implementation>
</feature>
