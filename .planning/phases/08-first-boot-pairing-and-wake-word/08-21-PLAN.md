<execution_notes>
- `proxy.ts` sits at the app root beside `app/` (Next 16 renamed middleware to proxy; Node runtime by default, so `node:crypto` and `node:fs` are available). Matcher: `['/((?!_next/static|_next/image|favicon.ico|login|api/auth/login).*)']`.
- The session key is read from `ARLOWE_DASHBOARD_STATE_DIR` via 08-09's `loadSessionKey`, which caches by mtime; a reset wipes the key, so every session dies with it.
- `grep -rn 'verifyAuth\|DASHBOARD_API_SECRET' runtime/dashboard --include='*.ts' --include='*.tsx'` must be empty afterwards (exclude `node_modules`).
- `GET` routes are covered by the proxy only; that is sufficient for reads. Do not add `requireSession` to GETs.
- The Playwright suite in `tests/*.spec.ts` is not run in CI; do not rely on it. If an existing spec now needs a login, note it in the SUMMARY rather than fixing it here.
</execution_notes>

  <name>Session enforcement</name>
  <files>runtime/dashboard/proxy.ts, runtime/dashboard/lib/auth/require-session.ts, the six route files</files>
  <behavior>
    - `proxy(GET /)` with no cookie → 307 to `/login?next=%2F`; with a valid cookie → next.
    - `proxy(GET /api/health)` with no cookie → 401 JSON; valid → next.
    - `proxy(GET /login)` and `POST /api/auth/login` are not matched by `config.matcher` (assert against the regex).
    - An expired or tampered cookie is treated as none.
    - Each of the six mutating handlers, called directly without a cookie → 401; with a valid cookie but `Origin: http://evil.example` and `Host: kitchen-test.local:3000` → 403; with a valid cookie and matching Origin → proceeds (mock the side effect: `execFile`, file writes).
    - `app/api/middleware/auth.ts` no longer exists.
  </behavior>
  <implementation>`requireSession` returns `NextResponse | null`; each handler starts `const denied = requireSession(request); if (denied) return denied;`. `benchmark`'s `POST()` gains a `request` parameter.</implementation>
</feature>
