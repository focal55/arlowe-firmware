<execution_notes>
- stdlib `http.server.ThreadingHTTPServer`. Responses carry `Connection: close` and `Cache-Control: no-store`. Portal URL is the IP literal `http://10.42.0.1/`.
- The portal owns no pairing logic. `make_server(state, on_submit, host, port, portal_host="10.42.0.1")`: `state` is a read-only view the flow updates (`status`, `error_kind`, `networks`, `last_form` without secrets, `ip_hint`); `on_submit(form)` is called on a new thread after the 200 is written and flushed.
- Validation rules: SSID 1-32 bytes UTF-8; PSK empty (open network) or 8-63 printable ASCII or exactly 64 hex; device name via `arlowe_hostname.validate_display_name` (the error message names the problem, never a banlist entry); dashboard password ≥ 8 chars and equal to its confirmation; claim code 20 Crockford chars after stripping `-` and spaces. A blank secret field is valid only when a previous submission's value is held (the flow passes `has_previous` flags in `state`).
- Error strings come from `runtime/pair/errors.py` (08-07). Import `MESSAGES`; do not restate them.
- The page shows, before submit: "Your Arlowe will be at http://<name>.local:3000" (a static sentence with `<name>` explained, no JavaScript required) and "If anything goes wrong, reconnect to <SSID> and reload this page" (research P11).
</execution_notes>

  <behavior>
    - `GET http://captive.apple.com/hotspot-detect.html` (Host header set) → 302 `Location: http://10.42.0.1/`; the same for `connectivitycheck.gstatic.com/generate_204`, `www.msftconnecttest.com/connecttest.txt`, `detectportal.firefox.com`.
    - `GET /` with Host `10.42.0.1` → 200 HTML listing the cached networks, with every field and the handoff sentences.
    - `POST /pair` valid → 200 "Switching networks…" page, then `on_submit` receives the parsed form exactly once.
    - `POST /pair` with each invalid field → 400 with the form re-rendered and that field's message; `on_submit` not called.
    - Body over 8 KB → 413.
    - `GET /status` → JSON `{status, error_kind, message}`.
    - After an error, `GET /` shows the message and pre-fills SSID and name but never a secret.
    - caplog and the server's stderr contain none of the submitted secrets.
  </behavior>
  <implementation>Keep `validate_form(fields, previous) -> dict | raises FormError(field, message)` pure so the flow can reuse it.</implementation>
</feature>
