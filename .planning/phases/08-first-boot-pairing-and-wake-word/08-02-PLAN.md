<objective>
Give the config schema a place for what pairing writes, and give Phase 8 one CI workflow that every later plan's tests land in.

Purpose: `additionalProperties: false` at the top level and in `device` means a daemon that writes an unknown key bricks the unit it just paired (CONTEXT). And today `buildSaveBody` discards the overlay unless it carries all eight required keys; a pairing overlay does not, so the first dashboard audio save would drop `identity.provisioning_url` (reset could no longer revoke), `owner`, `network` and the hostname. The workflow exists so later plans add test files to globbed directories instead of editing CI each time, which would make parallel plans collide on one file.
