Confirm with `grep -P '^pkg\t(iw|wireless-regdb|nftables)\t' docs/operations/phase-07.2-inputs.reference` before committing.
- **Setup-AP forwarding (ADR-0011).** `ipv4.method shared` enables forwarding and NAT to any other uplink. `arlowe-setup-ap.nft` (installed to `/etc/arlowe/nftables/arlowe-setup-ap.nft`, 0644) is `table inet arlowe_setup` with one chain `type filter hook forward priority filter - 10; policy accept;` holding `iifname "wlan0" drop` and `oifname "wlan0" drop`, preceded by `table inet arlowe_setup` + `delete table inet arlowe_setup` so reloading is idempotent (the usual `nft -f` idiom). A drop in any base chain is final, so NetworkManager's own shared-mode accept rules cannot override it. The appliance never routes, so the rule is harmless once paired. radio-init runs `nft -f <file>` (`ARLOWE_ROOT` prefixes the path for tests) and fails the unit if it fails. If `nft` reports a missing `nf_tables` family on hardware, set `ProtectKernelModules=no` with a comment; 08-27b checks `sudo nft list table inet arlowe_setup`.
- `ExecStart=/usr/bin/python3 /opt/arlowe/runtime/cli/radio-init` uses the declared python3 floor in `verify-unit-execstart.sh`, so no `ARLOWE_EXPECTED_UNDECLARED` entry is needed. Do not use `rfkill` or `iw` as an `Exec*` token.
- Unblock through `/sys/class/rfkill/rfkill*/soft` for entries whose `type` is `wlan`; this avoids depending on the `rfkill` binary. `ARLOWE_ROOT` prefixes `/sys` for tests.
- Do not set `WPA_COUNTRY` in `pi-gen/config` (#200's file, and `raspi-config do_wifi_country` rewrites `cmdline.txt`, which the A/B `boot-config.sh` owns).
- The polkit rule grants `wifi.share.protected`, not research's `wifi.share.open` (the AP is WPA2, ADR-0011).
- MEDIUM: the modprobe option applies only if `cfg80211` is a module. The runtime `iw reg set` covers the built-in case. 08-27b checks `lsmod | grep cfg80211` and `iw reg get` on hardware.
</execution_notes>
