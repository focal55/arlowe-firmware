- **Revoke request contract (08-19 implements the other side verbatim):** `POST <broker>/v1/certificates/revoke`, JSON body `{"device_id", "certificate_id", "issued_at", "signature"}`. `issued_at` is UTC `%Y-%m-%dT%H:%M:%SZ`. `signature` is base64 of the DER ECDSA-SHA256 signature by `device.key` over `json.dumps({"certificate_id":…, "device_id":…, "issued_at":…}, sort_keys=True, separators=(",", ":")).encode()`. No bearer token. Responses: 200 `{"revoked": true, "certificate_id"}`; 400 malformed; 401 bad signature, stale `issued_at` or wrong device; 5xx upstream.
- The revoke URL comes from the same resolution as provision (`--ca-broker-url`, then `identity.provisioning_url`). The CA comes from `ARLOWE_BROKER_CA_BUNDLE` exactly as for provision (`_ca_bundle`, `arlowe_cloud.py:83-92`); the CLI does not look for the FAT broker file itself. Callers resolve the broker with `arlowe_broker.resolve_broker` (08-18) and pass `--ca-broker-url` plus the env var.
- `request_certificate` rejects any non-https URL, so the CLI fixture must be TLS: generate a throwaway CA and a `127.0.0.1` server cert in the test with `cryptography`, wrap `http.server` with `ssl`, and point `ARLOWE_BROKER_CA_BUNDLE` at the CA. No PEM fixture is committed (07-04's build gate). `certificate_id` comes from `identity.json`; no certificate → exit 5 with `error: "not_provisioned"`.
- Everything must stay within the cryptography 38.0.4 API (`python-floor-bookworm`).
