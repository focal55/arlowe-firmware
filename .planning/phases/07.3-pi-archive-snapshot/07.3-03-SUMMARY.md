# Phase 7.3 Plan 03: Pi archive fetch/verify helper Summary

**`scripts/lib/pi-archive-fetch.py` proves all 92 Pi-archive debs (91 packages + prestera) by size and sha256 from four cache locations or an opt-in fetch. `verify-third-party.sh` check 9 runs it before every build and writes `build/.arlowe-pi-archive-paths` for plan 04a. A real fetch of the whole set from archive.raspberrypi.com verified 92/92, so the pool still serves every pinned version as of 2026-09-26.**

## Accomplishments

- Helper search order matches INSTALL.md exactly: `$ARLOWE_PI_ARCHIVE_DIR` -> `third_party/pi-archive/` -> `/var/cache/arlowe-build/pi-archive` -> `${XDG_CACHE_HOME:-~/.cache}/arlowe-build/pi-archive`. It never touches the network unless `ARLOWE_PI_ARCHIVE_FETCH=1`. Exit codes: 0 all verified, 1 any deb failed, 2 could not run (unreadable manifest or zero entries).
- Fetched bytes are checked while still named `.part`. On mismatch the `.part` is deleted, so the next run can never trust bad bytes.
- Every failure gets one `[pi-archive] FAIL <filename>: ...` line with expected and actual size or sha256.
- Check 9 is a 12-line wrapper. Check 8 (rpt-packages) is untouched and stays until 06b.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Helper crashed when the paths map's directory did not exist**
- **Found during:** Task 2, the real end-to-end fetch run standalone (no `build/` dir). All 92 debs fetched and verified, then `tempfile.mkstemp` raised FileNotFoundError.
- **Fix:** `os.makedirs(out_dir, exist_ok=True)` before writing the map. `[found-in-dir]` now writes its map into a not-yet-existing directory. Temporarily removing the fix made that case fail, which confirms it guards the bug.
- **Commit:** dfb2304

**2. [Rule 1 - Bug] Test fixtures for digest mismatch changed the size**
- Appending a byte tripped the size check first, so the sha256 path was never exercised. `[digest-mismatch]` and `[fetch-bad-bytes]` now use same-length different bytes.

**3. [Rule 2] `http.client.HTTPException` caught alongside OSError in the fetch retry loop**
- A truncated HTTP body (IncompleteRead) is not an OSError. Without this it would have been a traceback, not a named failure.

**4. Test count 11, not 10.** `[resolve-only-covered]` asserts both that the entry is mapped and that a tampered resolve_only deb fails. The assertion helper records the preceding command's status instead of `eval`-ing a string, which keeps shellcheck clean without SC2016 suppressions.

**5. `[fetch]` as root.** Root ignores `chmod 555`, so as root the case asserts only a clean fetch with no `.part`. The CI runner is non-root and gets the full XDG-fallback assertion.
