# Phase 7.3 Plan 04a: Pi flat repo builder and swap-back Summary

**`scripts/lib/pi-archive-repo.sh` builds a flat apt repo from exactly the 92 pinned debs. It re-hashes every copy and cross-checks each `Packages` stanza (name, version with epoch, arch, size, sha256) against the manifest. A real run over the 92-deb cache took 4.2 s and produced 171 MiB. `pi_archive_swap_back` in the new `scripts/lib/pi-archive-gate.sh` swaps that repo for pi-gen's stock `raspi.list`. It refuses to start without the template, and it asserts its own result. Nothing is wired into `build-image.sh`.**

## Deviations from Plan

1. **dpkg-scanpackages runs with no `/dev/null` override.** With an override, it prints a two-line warning, and the second line lists package names. That line cannot be filtered safely without also swallowing real warnings. Without one, the only stderr is `info: Wrote N entries`. The strict "fail on any other stderr" rule is kept.
2. **[Rule 2] A previous `O` is removed at the start, not at the end.** The plan swapped `O` out only on success, which leaves an old repo in place after a failed run. The must-have says "any disagreement leaves no repo behind", so the builder now removes it up front. `[stale-out-replaced]` still passes.
3. **[Rule 2] The swap-back checks the mtime clamp.** It prints a `[FAIL]` if `touch` fails. The must-have includes the clamp in "fails if any of that did not happen".
4. **The repo builder fails with its own message when the paths map is missing.** It points at check 9, following 03's instruction to fail hard rather than fall back.
5. **The `[extra-not-copied]` case is stronger than specified.** The stray deb sits in the same pool directory and is also listed in the paths map. It still never reaches `O` or `Packages`.
6. **The size is measured from ab28dd5, not from main.** Main lacks all of this phase's earlier commits, so `git diff main` reports 1,423 lines for the whole phase.
7. **Handoff correction.** 03 said `build/.arlowe-pi-archive-paths` was present on this host. It was not, and `build/` was empty. The cache itself (92 debs) was intact.

## Next Phase Readiness (handoff to 07.3-04b)

**Repo builder CLI**

`bash scripts/lib/pi-archive-repo.sh --manifest third_party/pi-archive/manifest.yml --paths build/.arlowe-pi-archive-paths --out <O>`

- Exits 0 only on success.
- Errors go to stderr as `[pi-archive-repo] FAIL ...` lines.
- Any failure leaves neither `<O>` nor `<O>.tmp`.
- It needs `python3-yaml` and `dpkg-dev` on the build host.

**Output layout**

`<O>/` holds only the 92 `*.deb`, `Packages` (plain, uncompressed, `Filename: ./<deb>`) and `SHA256SUMS`, which covers the debs and `Packages`. The rootfs source line is `deb [trusted=yes] file:/var/local/arlowe-pi-archive ./`. The overlay should run `sha256sum -c SHA256SUMS` inside the rootfs copy.

**Swap-back**

`pi_archive_swap_back <rootfs> <pigen_dir> <release> <source_date_epoch>`

- Call it as `sudo bash -c 'set -uo pipefail; source "$1"; pi_archive_swap_back "$2" "$3" bookworm "$4"' _ scripts/lib/pi-archive-gate.sh ROOTFS PIGEN SDE`.
- Returns 0 or 1. It prints `[OK]` or `[FAIL]` and never exits.
- It reads the template at `<pigen_dir>/stage0/00-configure-apt/files/raspi.list`. The 04b overlay must not delete or rename that file.

**Constants**

`PI_REPO_IN_ROOTFS=/var/local/arlowe-pi-archive` and `PI_REPO_LIST=arlowe-pi-archive.list` are defined in the library. 04b's overlay must use the same values.

**Placement**

The swap-back must run after the Pi gate and the completeness check, and before the apt-lists `rm` and Step 3's `du` (research Pattern 4).

**Not done here:** the stage0 overlay, the `copy_previous` carry, and the `build-image.sh` calls. No build was run, and `ARLOWE_INPUTS_ACCEPT=1` was not used.
