<objective>
Build the core of the manifest generator: the attribution rules that decide, package by package, which installed packages the Pi archive supplies and therefore must be pinned.

Purpose: SC1 requires the manifest to be generated from a real build's resolution, not typed by hand. <task type="auto">
  <name>Task 2: Implement generate (core) and wire the self-test into CI (GREEN)</name>
  <files>scripts/lib/pi-archive-manifest.py, .github/workflows/ci.yml</files>
  <action>
Create `scripts/lib/pi-archive-manifest.py` (executable, `#!/usr/bin/env python3`). Its module docstring states the attribution rule and the exit codes.

CLI: `pi-archive-manifest.py generate`. Required: `--installed-reference FILE` (only rows starting `pkg\t`), `--pi-list FILE` (repeatable, at least one), `--debian-list FILE` (repeatable, at least one), `--kernel-manifest FILE`, `--pool-base URL`, `--out FILE`. Optional: `--allow-local NAME` (repeatable).

- `open_index(path)`: plain text only in this plan. Parse RFC822 stanzas separated by blank lines; ignore continuation lines. Keep Package, Version, Architecture, Filename, Size, SHA256. Build an index keyed by `(name, version)` → list of stanzas.
- Attribution per installed `(name, version, arch)`, exactly as research Pattern 3:
  - `armhf` → failure.
  - Kernel names come from `kernel.debs[].filename`, taking the text before the first `_`. Strip the epoch from the installed version and compare it with `deb_version`: a mismatch is a failure, a match is excluded.
  - A Pi or Debian match needs the same name and version, with Architecture equal to `arch` or `all`.
  - Pi only → entry `{name, version (index Version, epoch kept), arch (stanza Architecture), filename (basename of Filename), size (int), sha256, url}`.
  - In both archives with the same SHA256 → skip, and count it. With different SHA256s → failure naming both digests.
  - In neither → skip if allow-listed, otherwise failure.
- A duplicate filename is a failure. Zero entries is a failure.
- Report ALL failures, then exit 1. Exit 2 on unreadable input or bad arguments.
- Output: write a temp file, then `os.replace`. Start with a header comment: GENERATED by scripts/lib/pi-archive-manifest.py; do not hand-edit; regenerate through the pin-bump procedure; `url` is how a deb is first obtained, `sha256` is the pin. Then `pool_base: "…"`, `packages:` and `resolve_only: []`.
  - One flow mapping per line, sorted by `(name, arch)`, keys in a fixed order.
  - Strings go through `json.dumps` (a valid YAML double-quoted scalar); `size` is a bare integer.
  - Print a summary: `[pi-archive] N packages, M resolve_only; skipped: D debian-identical, K kernel, L local`.

In `.github/workflows/ci.yml`, add a step to `build-inputs-resolve` after "Model pin verifier self-test":
