<execution_notes>
**The live Pi index moves several times a week, and it carries one version per package name.** The reference was recorded 2026-09-25 and all 97 Pi rows were in the live index that day. By the time this runs, some (raspi-firmware is the usual one) may have been superseded, and the generator will then correctly fail with "attributable to neither archive" for those rows. That is the generator working, not a bug. Do NOT paper over it by fetching the old deb from the pool and hashing it: that is trust-on-first-use with no signature behind it. Use the retained-index fallback described in Task 1 (`--pi-retained`), which gets apt to verify the index the reference build actually resolved against. If neither the live index nor a retained index covers every row, STOP and report; the remaining options (re-record the reference with a fresh build, or accept an unsigned digest) are decisions for the owner, not the executor.

- Run `git diff --shortstat main -- . ':(exclude).planning/**'` after Task 1 and at the end.
- **No build between now and plan 08 may run with `ARLOWE_INPUTS_ACCEPT=1`.** Plan 08 relies on the committed reference still being the pre-phase baseline, so that "0 pkg-row changes" means pinning reproduced the known-good set. A stray accept would silently move that baseline.
- Runs on the development machine with Docker (arm64 image; Apple Silicon runs it natively). Needs network.
- Don't name the build host in anything committed. Describe it as "the build host".
- Don't put debs in git. The `.gitignore` rule lands in this PR, before anything is staged (07.2-02 deviation #1 was exactly this omission).
- `third_party/rpt-packages/` stays in this PR. Plan 06b retires it. Its three digests are used here only as a one-off cross-check in `<verify>`, not in the committed test, because plan 06b deletes that file.
</execution_notes>

   - deletes `/etc/apt/apt.conf.d/docker-gzip-indexes` (otherwise lists are stored `.lz4`, which the generator refuses), removes `/etc/apt/sources.list.d/*.sources`, installs the overlay's `sources.list` (RELEASE→bookworm, exactly as `resolve-twice.sh` does) and `99arlowe-pinned`, runs `apt-get update`, and installs `gnupg python3 python3-yaml` (installing here is fine: this script generates a manifest, it doesn't measure a resolution);
   - dearmors the key to `/usr/share/keyrings/rpi-archive.gpg` and ASSERTS its fingerprint with `gpg --show-keys --with-colons` against a constant. Expected: `CF8A1AF502A2AA2D763BAE7E82B129927FA3303E`, the Raspberry Pi Archive Signing Key. Confirm that value against the printed output the first time you run this. If it differs, stop and report; don't edit the constant to match.
   - adds `deb [signed-by=/usr/share/keyrings/rpi-archive.gpg] http://archive.raspberrypi.com/debian bookworm main`. Use signed-by, not `trusted=yes`. apt's signature check is the whole point. If `--pi-retained` was given, it also adds `deb [signed-by=…] file:/pi-retained bookworm main`.
   - runs `apt-get update`, then ASSERTS that at least one `/var/lib/apt/lists/archive.raspberrypi.com_*binary-arm64_Packages` exists. If `--pi-retained` was given, it also asserts that at least one `_pi-retained_*binary-arm64_Packages` exists. Don't consult update's exit code. apt drops the list of a source whose signature fails, so the files are the evidence.
   - runs `python3 /w/scripts/lib/pi-archive-manifest.py generate --installed-reference /w/docs/operations/phase-07.2-inputs.reference`, with every Pi list (live and retained) as `--pi-list` and every `snapshot.debian.org_*binary-arm64_Packages` list as `--debian-list`, plus `--kernel-manifest /w/third_party/kernel/manifest.yml --allow-local axclhost --resolve-only firmware-marvell-prestera --pool-base http://archive.raspberrypi.com/debian --out /w/<out>`. The script lays them out in a temp mirror as `dists/bookworm/InRelease` and `dists/bookworm/main/binary-arm64/Packages`, so apt verifies the signature and the Packages hash exactly as the original build did. It must also print where to find these on the build host: `${WORK_DIR}/stage2/rootfs/var/lib/apt/lists/archive.raspberrypi.com_debian_dists_bookworm_{InRelease,main_binary-arm64_Packages}`, left there by the last build that passed the 07.2 diff gate.
