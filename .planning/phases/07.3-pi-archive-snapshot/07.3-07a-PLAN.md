Write `docs/architecture/0010-pi-archive-pinning.md` in ADR-0009's format. Status: **Proposed**. 07.3-09 moves it to Accepted with build evidence. Sections:

- **Context.**
  - The 97-package measurement.
  - One version per name in the index (2103 names / 2113 stanzas), so apt preferences cannot select a superseded version.
  - No Pi snapshot service.
  - The 07.2 diff gate detected drift, but forced a re-record on every publish and verified no bytes.

- **Decision.**
  - A generated manifest, one line per package, bootstrapped from a real build's reference crossed with an apt-verified index.
  - A host-side flat repo built from sha256-verified debs, indexed with dpkg-scanpackages.
  - `[trusted=yes]`: the trust anchor is the committed digest, enforced twice (the repo builder's cross-check, then apt's Packages SHA256 at install).
  - The stage0 overlay swap, carried forward by `copy_previous`.
  - The in-build gate and the two-direction check.
  - Record and pinned modes. Record mode still verifies the current pins at Step 1, by design.
  - The swap back to the stock `raspi.list` before measurement.

- **SC3: folded vs. separate.**
  - rpt-packages is folded in.
  - The kernel keeps `third_party/kernel/manifest.yml` and `stage0/02-firmware/00-run.sh`, sharing the no-live-source guarantee, the cache/verify pattern, and the completeness check (the kernel manifest counts as a legitimate origin). Reasons: the bump procedure differs (axcl compile re-proof, `expected_module_dirs`); the meta packages are deliberately in no repo; and a wholesale Pi regeneration must not be able to move the kernel.
  - **Expected** side effect: with no Pi source visible, `apt-get install ./*.deb` should install the local kernel debs, closing the 07.2 "Need to get 119 MB" open question. State it as an expectation, **to be confirmed in the 07.3-08/09 Outcome**, not as a fact.

- **Device apt stance.** The device ships the stock `raspi.list` and keyring (four reasons, research Pattern 4). An on-device `apt upgrade` is unsupported; the A/B image is the update channel.

- **Consequences.**
  - (a) Security ordering. A summary here; the details are in the 07.3 runbook.
  - (b) rpi-eeprom. A pin bump flashes every device's EEPROM at its next boot, outside A/B rollback.
  - (c) **"Bytes the project controls" holds only in a weak sense until a durable mirror exists.** Today the only copies are the build host's cache and a CI cache that GitHub evicts after 7 days unused. If Raspberry Pi prunes a pinned version and both caches are lost, the pinned image cannot be rebuilt. A durable mirror is a p1 follow-up. `ARLOWE_PI_ARCHIVE_DIR` makes it pluggable.
  - (d) CI determinism covers the stage0 and stage-arlowe lists, not upstream stage1/stage2.
  - (e) **Two paths still resolve against the live Pi archive and carry none of these pins:** `.github/workflows/build-image.yml` (an unpinned pi-gen action that bypasses the overlay) and `tests/phase-07.1/docker/Dockerfile` (a `deb [trusted=yes] http://archive.raspberrypi.com/debian bookworm main` source for the import-check container). Both are tracked as follow-ups.
  - (f) SKIP_IMAGES is believed to be a no-op at PIGEN_REF; confirmation is pending.

- **Alternatives rejected.** apt preferences; signing the flat repo; a per-stage bind mount; a record build for the first manifest; overlaying `stage2/02-net-tweaks/00-packages` to drop the prestera marker.

ADR-0009: add a "Superseded in part" note near the top. For the Pi archive side, ADR-0010 replaces "detected by the diff gate" with "pinned and installed from verified bytes". The kernel and Debian snapshot decisions stand.
