# Phase 7.3 Plan 05a: Pi archive completeness check Summary

**`pi-archive-manifest.py check` compares a rootfs's dpkg status against the manifest in both directions. It fails when a pinned package is missing or installed at another version or arch, which is how apt's silent substitution of Debian's build shows up. It also fails on an installed resolve_only package, on an installed package that no list accounts for, on a kernel package off its pin, and on any drift between the flat-repo index and the manifest. An empty installed set or manifest exits 2. It is fixture-proven and has not yet run against a built rootfs; 05b wires it in and 07.3-08 runs it.**

## Known limitation for 05b (not fixed; policy call)

`check` reuses `load_installed_status`, which counts only `Status: install ok installed`. A package left `half-configured`, `unpacked` or `half-installed` has files on disk, yet neither direction sees it: the forward pass reports a pinned package in that state as "not installed", and the reverse pass never sees an unpinned one. F7 once recorded axclhost as half-configured. If 05b wants a strict gate, the cheapest fix is to fail on any stanza whose Status is neither `install ok installed` nor a `config-files`/`not-installed` state. That changes what generate reads too, so I left it alone here.

## Next Phase Readiness (handoff to 07.3-05b)

The exact CLI:

```
python3 scripts/lib/pi-archive-manifest.py check \
    --status <rootfs>/var/lib/dpkg/status \
    --manifest third_party/pi-archive/manifest.yml \
    --kernel-manifest third_party/kernel/manifest.yml \
    --flat-list build/pi-archive-repo/Packages \
    --debian-list <snapshot Packages> [--debian-list ...] \
    [--allow-local axclhost ...]
```

- `--debian-list` must be given at least once and may be repeated. `--allow-local` is repeatable and defaults to none, so 05b must pass `--allow-local axclhost` explicitly. Index lists may be plain, `.gz` or `.xz`. `.lz4` and similar exit 2 with the `docker-gzip-indexes` hint.
- Exit 0 prints one line to stdout: `[pi-archive] check: N manifest packages installed at the pinned version, M installed packages attributed, 0 unattributed`. M is the full count of `install ok installed` stanzas.
- Exit 1 prints every failure to stderr as `[pi-archive] FAIL <msg>` and nothing to stdout. The messages:
  - `flat index only: <name> <version> <arch> <filename> <sha256>` / `manifest only: ...`
  - `<name>: pinned <version> <arch>, installed <v a>[, <v a>...]` or `..., not installed`
  - `<name> <version> <arch>: resolve-only package is installed`
  - `<name> <version> <arch>: kernel package off the kernel pin <deb_version>`
  - `<name> <version> <arch>: unattributed; in neither the flat repo, the Debian lists, the kernel pin nor --allow-local`
- Exit 2 prints `[pi-archive] ERROR <msg>` to stderr. The causes are an unreadable input, a status with no installed packages, a manifest with no `packages`, a malformed manifest or kernel manifest, or refused compression. Argparse usage errors also exit 2.
- The Debian lists must be the snapshot lists the build resolved against, taken before `pi_archive_swap_back` and the apt-lists rm. The 07.2 reference has 658 `pkg` rows, of which 91 are pinned here, so a missing Debian list would report several hundred unattributed packages.
- 05b's call must not contain the string `pi_archive_swap_back`, or it moves the anchor of 04b's awk order check.
