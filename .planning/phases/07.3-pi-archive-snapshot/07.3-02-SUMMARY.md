`gpg --show-keys` shows that `CF8A…303E` is the `pub` key (uid "Raspberry Pi Archive Signing Key", caps `scESC`) and `DE5C…3D6C` is its `sub` encryption subkey. The asserted constant matched on the first run and was not edited.

## Signature evidence (separate debian:bookworm arm64 container)

- `gpgv --keyring rpi.gpg InRelease` gave `Good signature from "Raspberry Pi Archive Signing Key"`, `using RSA key CF8A1AF502A2AA2D763BAE7E82B129927FA3303E`, signed on Fri Sep 25 14:35:19 2026 UTC.
- The decompressed `Packages.gz` hashes to `6d3c6db4…87f9`. That equals InRelease's `SHA256` line for `main/binary-arm64/Packages` (2167368 bytes).
- `92 of 92 entries match sha256+size in the gpgv-verified index`.
- Negative control: when apt is given `signed-by=` a freshly generated wrong key, it reports `NO_PUBKEY 82B129927FA3303E` and `The repository ... is not signed`, and leaves `raspberrypi Packages lists after update: 0`. This shows that the bootstrap's list-file assertion really is gated on the signature.

## Deviations from Plan

**1. [Rule 1 - Bug] `docker run` needed `-i`**
- **Found during:** Task 1, first bootstrap run (before the commit).
- **Issue:** Without `-i`, the heredoc never reaches `bash -s` in the container. The run exits 0, does nothing and writes no manifest. It is a silent pass.
- **Fix:** `docker run --rm -i ...`. This was fixed before `710c583`.

**2. [Rule 1 - Bug] Size figure corrected**
- **Issue:** The plan (and research) said about 230 MiB. The measured set is 178,122,788 B, about 170 MiB (packages 116,804,336 B plus prestera 61,318,452 B).
- **Fix:** The `.gitignore` comment and INSTALL.md state ~170 MiB.
- **Commit:** `6449a0c`

**3. Header lines:** the generator writes a 3-line header, not the 13 the plan estimated. The manifest is 98 lines.

**4. Output directory:** the host script creates `third_party/pi-archive/` before `docker run`, instead of creating it inside the container, so the directory is not root-owned on a Linux host.
