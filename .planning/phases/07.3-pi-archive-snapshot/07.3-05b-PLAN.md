**`verify_pi_archive_resolution ROOTFS`.** Return 2 if the lists dir is missing.
1. Collect the active lines from `sources.list` and `sources.list.d/*.list`, plus the `URIs:` lines from `*.sources`. If any names `archive.raspberrypi.com`, return 1.
2. If no list file starts with `PI_REPO_LIST_PREFIX="_var_local_arlowe-pi-archive_._Packages"`, return 1.
3. If any list file starts with `archive.raspberrypi.com_`, return 1 and name them. apt deletes a removed source's lists on update, so a survivor means that source was active.

On success, print the `ok` line.

**`pi_archive_run_check ROOTFS MANIFEST KERNEL_MANIFEST`.**
- Use `find -maxdepth 1` to collect the flat list (exactly one, else return 2) and the `snapshot.debian.org_*binary-arm64_Packages*` lists (at least one, else return 2) into bash arrays.
- Build `args=(check --status "$ROOTFS/var/lib/dpkg/status" --manifest … --kernel-manifest … --flat-list "$flat")`, append `--debian-list "$f"` for each list, and add `--allow-local axclhost`. - Run `python3 "$REPO/scripts/lib/pi-archive-manifest.py" "${args[@]}"`, with the repo root resolved relative to the library file.
- Propagate the rc. On rc 1, print a pointer to the runbook section on reading a check failure (07.3-07b). Also print the meaning of a pi-gen `Unable to locate package` / `has no installation candidate` error for a Pi-only name under pinning: the manifest lacks that package.
