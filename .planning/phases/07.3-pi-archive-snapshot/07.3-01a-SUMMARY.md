# Phase 7.3 Plan 01a: Pi archive manifest generator core Summary

**`pi-archive-manifest.py generate` attributes each installed package to the Pi archive, the Debian snapshot, the kernel pin, or the local allowlist, and fails on every ambiguous case. A fixture self-test covers each rule (14 assertions across 11 cases) and runs in CI.**

## Performance

- **Duration:** about 5 min
- **Completed:** 2026-09-26
- **Tasks:** 2 of 2
- **Files:** 2 created, 1 modified

## Accomplishments

- Pi-only packages become one sorted flow mapping per line: `name, version (epoch kept), arch, filename (no epoch), size, sha256, url`. Tested against the real `third_party/kernel/manifest.yml`, a 3-entry fixture produced `3 packages, 0 resolve_only; skipped: 1 debian-identical, 2 kernel, 1 local`. The recorder's `filename`+`sha256` walker, run over that output, found 3 pin rows.
- The run fails, and names the package, in these cases: the same name and version with different bytes in the two archives, a package in neither archive that is not on `--allow-local`, a kernel package whose version is not the `deb_version` pin, any `armhf` package, zero entries, a duplicate filename, and a Pi stanza that lacks Filename, SHA256 or a numeric Size.
- Exit 2 on an unreadable input or bad arguments, with a single `[pi-archive] ERROR` line and no traceback.
- Structure is ready for the plans that extend it. `open_index(path)` is the only index reader (01b adds `.gz`/`.xz` there). `load_installed_reference` is the only installed-set loader (01b adds `--installed-status` next to it). `main()` uses subparsers (05a adds `check`). `write_manifest` already accepts `resolve_only` entries.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The absence cases passed vacuously in RED**
- **Found during:** Task 1
- **Issue:** `[debian-only]`, `[identical-both]`, `[kernel-excluded]` and `[local-allowlist] absent` passed with no generator, because an empty manifest contains no packages at all.
- **Fix:** The shared `expect_py` prelude now asserts `pionly-a` is present before any case-specific assertion. After the fix, RED was 0 of 14.
- **Commit:** `45bbe6c`

**2. [Rule 3 - Blocking] The BSD sed on macOS does not understand `\t`**
- **Found during:** Task 1
- **Issue:** The kernel-mismatch fixture used `sed 's/^pkg\t…/'`, which works on GNU sed and silently does nothing on macOS.
- **Fix:** Replaced it with `awk -F'\t' -v OFS='\t'`, which behaves the same on BSD awk and on mawk (ubuntu).
- **Commit:** `45bbe6c`

**3. [Rule 2 - Missing Critical] Stanza integrity and conflicting Pi indexes**
- **Found during:** Task 2
- **Issue:** The plan does not say what happens when a Pi stanza lacks Filename, SHA256 or Size, or when two `--pi-list` files carry the same name and version with different sha256. Either case would crash the run or pin an arbitrary stanza.
- **Fix:** Both are now named failures.
- **Commit:** `6a960a5`

**4. Assertion count:** there are 11 cases, as planned. `[local-allowlist]` and `[format-and-determinism]` are split into several `[OK]` lines, so the output shows 14 assertions and the plan's "expect: 11 passed" reads as 14 in practice.

## Notes for 01b and later plans

- `make_fixtures <dir>` writes `pi/Packages`, `deb/Packages`, `kernel.yml` and `ref.txt`. The `gen` helper hard-codes those paths through `F`. For compressed variants, compress the files `make_fixtures` wrote rather than adding a second fixture set.
- `record()`, `expect_rc` and `expect_py` are generic. `expect_py` always checks the baseline `GOOD` manifest, not an arbitrary one, so parametrise it if 01b needs to check other outputs.
- The installed-reference reader accepts only `pkg` rows with exactly 4 tab fields and exits 2 on anything else. A dpkg status reader should share the `(name, version, arch)` tuple shape.
- The printed summary hard-codes `0 resolve_only`. 01b must pass real `resolve_only` entries to `write_manifest` and update the count.
- `pool_base` must be the archive root (`http://archive.raspberrypi.com/debian`), not the `…/pool/main/l/linux` value the kernel manifest uses.
- The diff budget is nearly spent. This plan alone is 397 lines against main, so 01b needs a fresh diff baseline (this branch, not main) or the local "PR" boundary has to be redefined. The phase is local-only, so there is no PR-size workflow to enforce the cap.
