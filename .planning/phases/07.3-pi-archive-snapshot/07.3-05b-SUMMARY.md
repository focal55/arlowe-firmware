## Deviations from Plan

### Orchestrator-directed addition

**1. The dpkg-status cleanliness gate in `pi_archive_run_check`**
- **Why:** `check` counts only `install ok installed` stanzas (05a known limitation). A Pi package that is half-configured, unpacked or half-installed has files on disk but escapes both directions of the check.
- **What:** Before discovering the lists, `_pi_unclean_status` names every stanza whose Status is neither `install ok installed` nor `deinstall ok config-files`, as `name: status` (or `no Status`). The function then returns 1. Case: `[run-check-dpkg-unclean]`.
- **Commit:** 3f10e1b

### Additions within the plan's intent

- **An extra test case, `[run-check-fail-propagates]`.** The plan asked for rc propagation and a runbook pointer on rc 1, but none of its cases exercised rc 1 from the checker. This case does, and the `|| true` mutation proves it bites.
- **The rc 1 runbook pointer names a document that does not exist yet.** It points to `docs/operations/phase-07.3-pi-archive-pinning.md` section 3, "Reading a failure". 07.3-07b writes that section under that name.

### Adaptations to the repo as merged

- **The test file had no fixture-rootfs helper for apt/dpkg.** Its `setup()` only builds the swap-back fixture, so the new `groot()` builder sits beside it and does not extend it. The Packages `stanza` helper is a local version of the manifest test's helper, with Size fixed at 1.
- **Library return codes.** The header now documents 0/1/2 (2 = could not test). Before, it documented only 0/1.

## Risk for 07.3-08 (read before the first real build)

**axclhost may trip the new dpkg-status gate on every real build.** `pi-gen/stage-arlowe/01-runtime/00-run-chroot.sh:243-250` tolerates a non-zero `dpkg -i` of the axcl deb and says outright: "this leaves axclhost in a half-configured dpkg state". F7 recorded the same thing. The committed 07.2 reference cannot settle it, because `dpkg-query -W` lists all states. arlowe-1 did not resolve from this host, so I could not read a real status file.

If the postinst still fails in-chroot, 07.3-08's build fails at this gate with `axclhost: install ok half-configured`. That is the gate doing its job: the image ships a package dpkg considers broken, and first-boot `apt` will try to reconfigure it. I did not add an axclhost exemption, because that would hollow out the orchestrator's decision. If it fires, there are two options:
- (a) Make the axcl install finish cleanly in the chroot (preferred; this is the F7 DKMS/first-boot question).
- (b) Consciously exempt `axclhost` from the status gate only, with the reason recorded.

This is the owner's call, and it should be made before 08, not during it.
