# Phase 7.3 Plan 04b: Stage0 flat-repo source and build wiring Summary

**In pinned mode (the default), stage0 now copies `build/pi-archive-repo` into `/var/local/arlowe-pi-archive` and re-runs `sha256sum -c` on that copy. It deletes `raspi.list` and writes `deb [trusted=yes] file:/var/local/arlowe-pi-archive ./` as the only Pi source. `build-image.sh` builds that repo before pi-gen and passes both variables across `sudo`. It swaps the repo back out after the snapshot gate and before the apt lists are removed. It refuses any mode other than `pinned`. The mechanism is complete in code but has not run inside pi-gen; that happens in 07.3-08.**

## Deviations from Plan

1. **RED was 4 of 5 failing, not 5 of 5.** `[record]` passes against the unmodified overlay because upstream's behaviour is record mode. Forcing it to fail would have needed a contrived assertion.
2. **[Rule 1] The test executes the overlay instead of running `bash FILE`.** `bash FILE` ignores the `#!/bin/bash -e` shebang. Without `-e`, a failed `sha256sum -c` does not stop the script. The script would go on to write the flat-repo list, and the tampered case would test a behaviour pi-gen never runs. pi-gen executes run scripts directly, so the test does the same. The change landed in the GREEN commit.
3. **[Rule 2] An empty `PIGEN_RELEASE` fails the build.** If the `sed` finds no `RELEASE=` line, swap-back writes `debian/  main`. Its own grep then matches that same empty release, so it reports success. `build-image.sh` now fails first.
4. **The flat-repo list is created with `install -m 644 /dev/null` and then written.** This makes the "mode 644" requirement explicit instead of leaving it to the umask. It follows the overlay's existing `00-temp.list` pattern.
5. **Placement of the mode check.** It sits right after `export ARLOWE_WORKTREE_CLEAN`, which is the first line after the SOURCE_DATE_EPOCH export block. It still runs before the log line and before Step 1.
