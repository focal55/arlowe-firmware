## Deviations from Plan

### Handoff-directed addition

**1. [Rule 3 - Blocking] build-image.yml had no Pi archive debs, so check 9 failed there (the gap 03 noted)**
- **Fix:** a manifest-keyed `actions/cache` on `~/.cache/arlowe-build/pi-archive`, then a separate step that fetches on a miss as the runner user. That step exports `ARLOWE_PI_ARCHIVE_DIR` and adds it to the `sudo --preserve-env` list of the build-image.sh step. Without that, root's `~` would miss the runner's cache.
- **Caveat:** this is actionlint-clean but has never run. The workflow's usimd/pi-gen-action step runs pi-gen before build-image.sh, and whether that path sees the flat repo is the same untested question the workflow already carried. 07.3-08 builds on the dev unit, not through this workflow.
- **Commit:** 94d7a4d

### Additions within the plan's intent

- **`PI_ARCHIVE_MANIFEST` override in the probe.** It is used only to prove the failure paths against tampered copies.
- **`--state` lists every live version when an index carries more than one.** It does not pick one.
- **A second RED case (empty `Packages`).** It showed that the index check alone passes on an empty repo and that the resolution is what fails it.

### Adaptations to the repo as merged

- The flat repo holds 92 debs (91 packages + 1 resolve_only), so the retention probe issues 92 HEADs, not the ~93 the plan estimated.
- `grep -c` in `resolve_once` carries `|| true`. It exits 1 on a zero count, which is the expected live-URI result, and without the guard every run would have looked like a resolver failure.
