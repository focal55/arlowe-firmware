<objective>
Verify every pinned Pi-archive deb before the build, with one Python helper called from a thin `verify-third-party.sh` stanza, so the build has digest-proven bytes to build its flat repo from.

Purpose: "installed from bytes the project controls" starts with having those bytes locally and proving them. Check 7 (kernel) and check 8 (rpt-packages) already duplicate a ~150-line bash fetch/verify loop; a third copy for ~92 debs is how the three drift apart (research, Don't Hand-Roll). The Python helper follows the `scripts/lib/verify-models.py` precedent.

Output: `scripts/lib/pi-archive-fetch.py`, a new check 9 in `verify-third-party.sh`, a fixture self-test, CI wiring.

Scope boundary: check 8 (rpt-packages) is NOT removed here. It keeps verifying the same three debs until plan 06b retires `third_party/rpt-packages/` together with its other consumer (`resolve-twice.sh`'s `RPT_ONLY_PACKAGES`). The overlap is harmless duplication for a few PRs and keeps this one under 400 lines.

**Honest PR size: ~305 lines.**

- test 125: harness 15, fixtures 30, 10 cases at 8 lines each = 80
- verify-third-party.sh +47: stanza 16, header and usage lines 8 (see Task 2), comment 8, plus 15 of slack for adapting to real variable names

130 + 125 + 47 + 3 = 305.

**Deviation from research, deliberate:** research names a single-directory pointer file `build/.arlowe-pi-archive-cache` like the kernel's. This plan writes a paths map (`filename<TAB>absolute path`) instead. The kernel pointer needs a consolidation step when debs resolve from several directories (check 7 has ~30 lines for it); plan 04a's repo builder copies every deb into `build/pi-archive-repo/` anyway, so a map makes consolidation unnecessary rather than re-implemented.

**`scripts/lib/pi-archive-fetch.py`** (executable). Docstring states: purpose, the search order, that `url` is how a deb is obtained the first time while the sha256 is the pin, exit codes 0 all verified / 1 any entry failed / 2 could not run.
- Args: `--manifest`, `--repo-root`, `--paths-out`.
- Entries = `packages` + `resolve_only`; zero entries → exit 2.
- Remove `--paths-out` FIRST, unconditionally, so a failed run can never leave a stale map (the kernel check's "never leave a stale pointer behind" rule).
- Candidate dirs, in order: `$ARLOWE_PI_ARCHIVE_DIR` (if set), `<repo-root>/third_party/pi-archive`, `${ARLOWE_PI_ARCHIVE_SHARED_CACHE:-/var/cache/arlowe-build/pi-archive}`, `${XDG_CACHE_HOME:-~/.cache}/arlowe-build/pi-archive`. Take the first that has the file.
- If not found and `ARLOWE_PI_ARCHIVE_FETCH == "1"`: fetch dir = the first of the shared cache or the XDG cache that can be created and written, printing a one-line note when falling back. Download with `urllib.request` (timeout 60 s, 3 attempts) to `<file>.part`, verify size and sha256 of the `.part`, and only then `os.replace` it to the final name. On mismatch, delete the `.part` and fail. The download is verified BEFORE it gets a name the next run would trust.
- Verify every located file by size, then by sha256 (1 MiB chunks). Report each failure as one line: `[pi-archive] FAIL <filename>: …`. Include expected and actual on a mismatch, plus a remedy line: if deliberate, regenerate through the pin-bump procedure; never hand-edit.
- Collect all failures; exit 1 if any. Otherwise write the map atomically (temp + `os.replace`), sorted by filename, and print `[pi-archive] N debs verified (M fetched)`.
