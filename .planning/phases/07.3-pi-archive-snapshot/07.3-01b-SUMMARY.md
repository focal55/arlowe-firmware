# Phase 7.3 Plan 01b: Generator input variants Summary

**`pi-archive-manifest.py generate` now reads `.gz`/`.xz` indexes and dpkg status files, and emits `--resolve-only` removal markers such as prestera under `resolve_only:` with a `why`. Eight new self-test assertions were red first and are green now (22/22).**

## Performance

- **Duration:** about 4 min
- **Completed:** 2026-09-26
- **Tasks:** 2 of 2
- **Files:** 2 modified

## Accomplishments

- `open_index` dispatches on suffix: plain, `.gz` (gzip) and `.xz` (lzma). `.lz4`, `.bz2`, `.zst`, `.lzma` and `.Z` exit 2 with `apt in a docker image stores .lz4 lists because of /etc/apt/apt.conf.d/docker-gzip-indexes; delete that file before apt-get update`. A corrupt `.gz` gives `[pi-archive] ERROR cannot read bad.gz: Not a gzipped file`, rc 2, and no traceback.
- `--installed-status` reads only `Status: install ok installed` stanzas and returns the same `(name, version, arch)` tuples as `load_installed_reference`. It exits 2 if an installed stanza lacks Package, Version or Architecture. argparse enforces that exactly one of the two installed-set flags is given, and giving both gives rc 2.
- `--resolve-only NAME[=VERSION]` fails if NAME is installed at any version. Otherwise it must resolve to exactly one (version, sha256) across all `--pi-list` files, and the failure message lists what it found, e.g. `found 2: 1:2.0-1, 1:2.0-2` or `found 0: none`. Duplicate filenames are now checked across `packages` and `resolve_only` together. The stdout summary reports the real resolve_only count.
- Refactor: `parse_stanzas` (shared by the index and status readers), `pi_entry`, `complete`, and `duplicate_filenames` were extracted from `attribute`. The 01a behavior is unchanged, and all 14 01a assertions still pass.

## Deviations from Plan

**1. [Rule 3 - Blocking] Test helpers generalized**
- **Issue:** `gen`/`expect_rc` hard-coded `--installed-reference` and a single `pi/Packages`, and `expect_py` only read the baseline. The status, multi-list and resolve-only cases cannot be expressed through them.
- **Fix:** `genx`, `expect_rcx`, `expect_py_on` and `same_as_good` were added. `gen`, `expect_rc` and `expect_py` are now thin wrappers, so the 01a cases are untouched. Every new Python assertion still goes through the `pionly-a` prelude.
- **Commit:** `95dd784`

**2. [Rule 2 - Missing Critical] resolve-only checks the bytes, not only the version**
- **Issue:** The plan says "exactly one distinct version must remain". Two Pi lists with the same version but different sha256 would otherwise pin whichever stanza came first.
- **Fix:** It now requires exactly one (version, sha256) pair, and the entry's stanza must have Filename, SHA256 and a numeric Size.
- **Commit:** `3d4084b`

**3. [Rule 2 - Missing Critical] A malformed installed status stanza exits 2**
- **Issue:** An `install ok installed` stanza that lacks Version or Architecture would have crashed with a KeyError.
- **Fix:** It is now an `InputError`, handled the same way as a malformed reference row. The fixture does not exercise this path.
- **Commit:** `3d4084b`

**4. Assertion count:** the plan says "16 passed". There are 16 cases (11 + 5), but `[compressed]` and `[resolve-only-ambiguous]` produce several `[OK]` lines each, so the output reads 22.

## Notes for 07.3-02 and later

- Bootstrap call: `generate --installed-reference <ref> … --resolve-only firmware-marvell-prestera`. If a second Pi list carries prestera at another version, pin it with `=VERSION` or the run fails and lists them.
- 07a record mode: pass `--installed-status <rootfs>/var/lib/dpkg/status`. Apt lists read from a docker container are `.lz4` unless `/etc/apt/apt.conf.d/docker-gzip-indexes` is deleted before `apt-get update`, and the generator refuses them.
- Both `packages` and `resolve_only` rows carry `filename` + `sha256`, so the 01a pin walker (and a future `check` mode) will see prestera as a pinned input. That is intended: it is in the cache.
- `resolve_only` entries are sorted by name and have no `(name, arch)` tiebreak. Two resolve-only specs for the same name at different arches are not a case this phase has.
